يعمل Klex Bot في بيئات خارجية متصلة عبر MCP (بروتوكول سياق النموذج). يمكن لخادم MCP إتاحة جهاز كمبيوتر كامل أو تطبيق مثل GitHub أو Google Workspace. وتتصل أجهزة الكمبيوتر عبر MCP أيضًا.

تحافظ بيئة Bot الخاصة به على تشغيله وتدير ذاكرته. أما أجهزة الكمبيوتر والتطبيقات المتصلة فهي البيئات التي ينفذ فيها عمله.

<a id="choose-what-to-connect"></a>

## اختر ما تريد توصيله

- **أجهزة الكمبيوتر** توفر بيئة متصلة يستطيع Bot العمل فيها.
- **التطبيقات** تتيح بيئة التطبيق عبر خادم MCP.

يوفر Klex مجموعة من خوادم MCP المدمجة، ويمكنك توصيل خوادم MCP أخرى أيضًا. اختر البيئات وفقًا للعمل الذي تريد أن يؤديه Bot.

<a id="manage-a-bots-access"></a>

## إدارة وصول Bot

وصّل التطبيقات وأجهزة الكمبيوتر التي يحتاجها Bot لعمله. في معظم اتصالات MCP، يعمل Bot من خلال حسابه أو هويته الخاصة، بالصلاحيات المهيأة له.

<Tabs syncKey="hosting" hash={false}>
<Tab title="الاستضافة السحابية">

افتح Bot في Klex Cloud واستخدم **Connectors** لإدارة اتصالات التطبيقات، و**Computers** لإدارة أجهزة الكمبيوتر المتصلة. يمكنك أيضًا مراجعة **Activity**.

</Tab>
<Tab title="الاستضافة الذاتية">

في تطبيق Klex، استخدم **Settings → MCP Servers** لإدارة اتصالات الخوادم. راجع [MCP وKlex Bots](/bot/concepts/mcp#add-a-remote-server-in-the-self-hosted-app) للاطلاع على الخطوات. استخدم **Settings → Logs** لمراجعة معلومات التشخيص المحلية.

</Tab>
</Tabs>

اضبط صلاحيات حسابات Bot والتطبيقات المتصلة مباشرةً في تلك الحسابات والتطبيقات. توصيل الخادم ومنح الحساب حق الوصول قراران منفصلان. تحقق من كليهما عند تحديد ما يمكن لـ Bot الوصول إليه والقيام به.

للاطلاع على الصورة العامة، راجع [كيف تعمل Klex Bots](/bot/concepts/how-bots-work). ولمعرفة مكان تخزين المحادثات والذاكرة، راجع [دليل البيانات](/bot/concepts/data-directory).
