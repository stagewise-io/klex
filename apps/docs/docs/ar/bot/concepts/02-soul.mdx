## إنشاء Soul وتحديثه

استخدم واجهة Admin API الخاصة بالبوت لإنشاء Soul أو تحديثه بناءً على تعليمات. أرسل `POST /v1/soul` لإنشاء Soul من البداية، أو `PATCH /v1/soul` لتحديث Soul موجود. استخدم `GET /v1/soul` لقراءته. راجع [الوصول إلى Admin API المحلية](/bot/guides/observability#access-the-local-admin-api) لمعرفة كيفية الوصول وإرشادات الأمان.

يستخدم إنشاء Soul نماذج الدردشة المُعدّة ويُحفظ الناتج عند نجاح العملية. على سبيل المثال، يمكن أن تصف التعليمات عمل البوت والنبرة المفضلة وأسلوبه في اتخاذ القرارات. راجع Soul الناتج وحدّثه عند الحاجة. احفظ Soul قبل إرسال عمل جديد إلى البوت.

## التخزين والوصول

يُحفظ Soul في [دليل بيانات](/bot/concepts/data-directory) البوت. تستطيع واجهة Admin API الخاصة بالبوت قراءته وإنشاء Soul جديد أو محدّث من تعليمات المسؤول. لا تتوفر في الجلسة العادية أداة لكتابة Soul.

## إذا لم يكن للبوت Soul

يحتاج البوت إلى Soul غير فارغ لمعالجة العمل العادي. بدونه، يتخطى العمل الجديد ويتخلص من المحتوى المضاف حديثاً إلى سجل الجلسة، ولا يضع العمل المتخطى في قائمة انتظار. أنشئ Soul قبل إرسال مدخلات جديدة.
