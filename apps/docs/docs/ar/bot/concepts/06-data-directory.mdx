يحفظ كل بوت Klex محادثاته وذاكرته في دليل بياناته الخاص. بالنسبة إلى البوت المستضاف على السحابة، يوجد هذا الدليل في بيئة سحابية. أما البوت المستضاف ذاتياً فيوجد الدليل في المجلد المحلي الذي يحتفظ ببياناته.

يمكن للمسؤولين الوصول إلى المحادثات والذاكرة عبر واجهة Admin API الخاصة بالبوت. تعمل وحدة تحكم Klex Cloud كوكيل عكسي وواجهة أمامية لواجهة Admin API الخاصة بكل بوت.

## العثور على بوت مستضاف ذاتياً

عند تشغيل تطبيق Klex 0.30.1 المستضاف ذاتياً بصورة تفاعلية، يُبحث عن البوتات افتراضياً في `~/.klex/agents`. إذا ضُبط `KLEX_HOME`، يُستخدم مجلد `agents` ضمن ذلك المسار. يمكنك تحديد دليل مباشرة باستخدام `--data-dir`؛ ولهذا الخيار الأولوية على `KLEX_DATA_DIR`.

على سبيل المثال، لفتح بوت تعرف دليل بياناته:

```sh
klex --data-dir /path/to/bot
```

استبدل مسار المثال بدليل البوت الفعلي. لإنشاء بوت وإعداده دون واجهة طرفية، راجع [البدء السريع](/bot/quickstart).

## حماية البيانات

قد يحتوي الدليل على معلومات حساسة مثل الإعدادات وبيانات الاعتماد. قيّد الوصول باستخدام أذونات نظام التشغيل واحمِ أي نسخ تنشئها. على الأنظمة التي تستخدم أوضاع ملفات Unix، يطلب Klex 0.30.1 أذونات وصول للمالك فقط عند إنشاء الدليل؛ ولا يغيّر أذونات الأدلة الموجودة. يستخدم Windows قوائم التحكم بالوصول.

قبل حذف البيانات أو نقلها، تحقّق من إجراءات النسخ الاحتياطي والاستعادة الخاصة بك. لا تصف هذه الصفحة إجراء ترحيل أو استعادة مدعوماً، أو فترة الاحتفاظ بالبيانات، أو كيفية تعامل الجهات الخارجية مع البيانات.
