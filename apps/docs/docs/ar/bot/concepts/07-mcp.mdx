يربط [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) بين Klex Bot والبيئات الخارجية. يمكن لخادم MCP إتاحة جهاز كمبيوتر أو تطبيق، ويستخدم Bot الإمكانات التي يوفرها الخادم للعمل فيه.

يوفر Klex خوادم MCP مدمجة ويدعم خوادم MCP أخرى. تعتمد الإمكانات المتاحة على الخادم:

- تتيح **الأدوات** لـ Bot طلب إجراءات أو معلومات من الخادم.
- توفر **الموارد** محتوى يمكن لـ Bot اكتشافه وفتحه.
- يمكن أن تنقل **الإشعارات الفورية** الرسائل والأحداث الأخرى عندما يدعم الخادم [امتداد Klex MCP Push Notifications](https://github.com/stagewise-io/klex/tree/main/packages/mcp-extension-push-notifications).
- يسمح **MCP Events & Triggers**، وهو امتداد MCP في مرحلة المسودة، لـ Bot باكتشاف أحداث الخادم المدعومة ومراقبتها. تستمر المراقبة عبر المحادثات وإعادة التشغيل، لكن قد تُفقد الأحداث أثناء التوقف. إعداد المراقبة لا يضبط الخدمة الخارجية تلقائيًا.

يمكن لإمكانات MCP هذه أن تدفع Bot إلى العمل عند وصول رسالة أو حدوث تغيير في تطبيق. وهي تعتمد على دعم الخادم المتصل وإعداده، ولا تتطلب بوابة منفصلة خاصة بـ Klex.

<a id="adding-a-server"></a>

## إضافة خادم

يمكنك إدارة اتصالات MCP الخاصة بـ Bot في لوحة تحكم Cloud. ويمكن لـ Bot أيضًا إضافة خادم MCP بعيد جديد عبر HTTP أو HTTPS بنفسه. لا يمكن لوظيفة إضافة الخادم تعديل إعدادات الخوادم الموجودة أو حذفها. إذا كان الخادم الجديد يتطلب OAuth، يمكن للمستخدم منحه الإذن في واجهة Cloud.

لا تتصل إلا بالخوادم التي تثق بها. يجعل الاتصال إمكانات الخادم متاحة لـ Bot، ويعتمد الوصول داخل التطبيق أيضًا على الحساب والصلاحيات المضبوطة فيه. راجع اتصالات Bot وامنح حساباته الصلاحيات التي تحتاجها فقط. راجع [الاتصالات بأجهزة الكمبيوتر والتطبيقات](/bot/concepts/brain-and-computers) لمعرفة المزيد عن إدارة الوصول.

يتصل Bot بالتطبيق عبر MCP. يكون حساب Bot داخل التطبيق منفصلًا عن الاتصال.

<a id="add-a-remote-server"></a>

### إضافة خادم بعيد

<Tabs syncKey="hosting" hash={false}>
<Tab title="مستضاف في السحابة">

1. في Klex Cloud، افتح Bot واختر **Connectors**. تحتاج إلى صلاحية مالك المؤسسة أو المسؤول لإدارة الموصلات.
2. اختر **Connect an MCP** من قائمة الموصلات، وأدخل عنوان الخادم واسمه، وأضف أي رؤوس مطلوبة ضمن **Advanced options**.
3. اختر **Connect** وأكمل التفويض إذا طُلب منك ذلك. تحقق من حالة الاتصال قبل الاعتماد على الخادم.

</Tab>
<Tab title="مستضاف ذاتيًا">

<a id="add-a-remote-server-in-the-self-hosted-app"></a>

في تطبيق Klex التفاعلي، يمكنك إضافة خادم HTTP يدعم النقل المتدفق:

1. افتح **Settings → MCP Servers** واضغط على `a`.
2. أدخل اسمًا فريدًا للخادم وعنوان HTTP أو HTTPS كاملًا. استخدم HTTPS للخدمات البعيدة التي تنقل بيانات اعتماد.
3. إذا كان الخادم يتطلب رؤوسًا مخصصة، اضغط على `a` لإضافة كل اسم وقيمة. تعامل مع قيم بيانات الاعتماد على أنها أسرار.
4. اضغط على `s` لإضافة الخادم، ثم تحقق من حالته في قائمة الخوادم. حفظ الإعدادات وحده لا يعني أن الخادم متصل.

لفحص خادم، حدده واضغط Enter. تعرض شاشة التفاصيل حالته وطريقة النقل وعدد الأدوات ودعم الإشعارات الفورية. من هناك، يعدّل `e` إعداداته ويحذفه `d` بعد التأكيد. عند الحذف، يحذف Klex بيانات اعتماد OAuth المحلية ويحاول إبطال الرمز إذا كان الموفر يدعم ذلك. قد يفشل الإبطال، لذا تحقق من صلاحيات الحساب بشكل منفصل في التطبيق المتصل.

</Tab>
</Tabs>

لتفويض OAuth عبر واجهة Cloud، يجب أن يكون Bot مسجّلًا في Cloud وأن يكون نفق Cloud متصلًا. لا يمكن لـ Bot مستقل غير مسجّل في Cloud استخدام مسار التفويض هذا عبر Cloud.

<a id="if-a-connection-needs-attention"></a>

## إذا كان الاتصال يحتاج إلى معالجة

قد يحتاج الخادم إلى تفويض أو يفشل في الاتصال. تحقق من حالة الاتصال وأكمل أي تفويض مطلوب. إذا استمر تعذر الاتصال، فتحقق من عنوان الخادم وبيانات الاعتماد ومدى توفر الخادم. لا يمكن لـ Bot استخدام سوى الإمكانات التي يتيحها خادم متصل.
