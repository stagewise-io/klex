في [لوحة Klex Cloud](https://cloud.klex.bot)، يمكنك رؤية ما يفعله البوت والدردشة معه.

يمكن للمسؤولين أيضًا مراجعة محادثات البوت ومهاراته عبر Admin API الخاصة به. توفر لوحة Cloud واجهة لـ Admin API الخاصة بكل بوت. لمعرفة مكان تخزين البيانات، راجع [دليل البيانات](/ar/bot/concepts/data-directory).

<a id="review-activity-and-diagnostics"></a>

## مراجعة النشاط والتشخيص

<Tabs syncKey="hosting" hash={false}>
<Tab title="مستضاف على Cloud">

في Klex Cloud، افتح البوت واختر **Activity** لمراجعة عمله الأخير. اختر نشاطًا لرؤية تفاصيله، واستخدم **Load older activity** لرؤية المزيد عند توفره. قد لا يتضمن عرض النشاط جميع الأحداث السابقة.

</Tab>
<Tab title="مستضاف ذاتيًا">

<a id="check-self-hosted-diagnostics"></a>

في تطبيق Klex التفاعلي، افتح **Settings → Logs** لمراجعة سجلات التشغيل الأخيرة. استخدم مفاتيح الأسهم للتمرير، و`l` لتغيير الحد الأدنى للمستوى المعروض، و`v` لتغيير نمط العرض. تغيير المستوى المعروض لا يفعّل بالضرورة جمع سجلات إضافية.

يحتفظ العارض في الذاكرة بما يصل إلى 500 إدخال ملتقط للعملية الحالية، لذا قد لا تعود الإدخالات الأقدم متاحة. سجلات التشغيل ليست سجلًا كاملًا لمحادثات البوت أو نتائج المهام. في وضع headless، يكتب Klex السجلات في وحدة التحكم بدلًا من استخدام العارض التفاعلي.

للحصول على تفاصيل الإصدار والاتصال، افتح **Settings → Debug Information**. تعرض نسخة Klex ودليل البيانات وحالة التسجيل في Cloud والنفق عند توفرها. راجع السجلات والتشخيصات بحثًا عن معلومات حساسة قبل مشاركتها.

</Tab>
</Tabs>

<a id="if-a-bot-does-not-respond"></a>

## إذا لم يستجب البوت

تحقق من كل جزء من المسار، بدءًا من البوت وانتهاءً بمصدر الرسالة:

1. **تحقق من أن البوت يعمل.** بالنسبة إلى بوت مستضاف ذاتيًا، تحقق من عمليته أو خدمته. إذا فعّلت مستمع الحالة الاختياري، فتحقق من نقطة نهاية الجاهزية. نجاح الفحص لا يثبت أن النموذج أو الاتصالات تعمل.
2. **تحقق من الوصول إلى النموذج.** تأكد من إعداد مزود واختيار نموذج محادثة. إذا فشلت الطلبات، فتحقق من حساب المزود وخدمته. راجع [النماذج](/ar/bot/concepts/models).
3. **تحقق من الاتصال والحساب.** للرسالة الواردة من تطبيق متصل، تحقق من حالة خادم MCP والتفويض المطلوب ووصول حساب البوت إلى المحادثة. يعتمد تسليم الأحداث أيضًا على إمكانات الخادم. راجع [MCP وبوتات Klex](/ar/bot/concepts/mcp#if-a-connection-needs-attention).
4. **راجع النشاط والسجلات المتاحة.** ابحث عن الأخطاء قرب وقت الطلب. استخدم لوحة Cloud عند توفرها أو تشخيصات الاستضافة الذاتية أعلاه. قد تكون السجلات والنشاط غير مكتملة؛ غياب إدخال وحده لا يحدد موضع فشل التسليم.

راجع التشخيصات بحثًا عن معلومات حساسة قبل مشاركتها. لا تضمّن بيانات الاعتماد في طلب الدعم.

<a id="review-activity-with-the-admin-api"></a>

## مراجعة النشاط باستخدام Admin API

يمكن للمسؤولين الذين يستخدمون Admin API:

- عرض قائمة مثيلات الجلسات المحفوظة باستخدام `GET /v1/sessions`، ثم استرجاع رسائل جلسة باستخدام `GET /v1/sessions/{instanceId}/messages`. اتبع `nextCursor` لاسترجاع الصفحات الأقدم. قد تكون بعض الرسائل القديمة قد اقتُطعت؛ تحقق من `trimmedMessageCount`.
- فحص نشاط الجلسات المباشر باستخدام `GET /v1/introspect/sessions`. قد تتضمن معلومات الجلسة `childSessions`، مثل جلسات استرجاع الذاكرة أو كتابتها أو الاستشارة النشطة. تُحذف الجلسات الفرعية المنتهية، لذا فهذا ليس سجلًا كاملًا.
- الاستعلام عن استخدام استدعاءات النموذج المسجل باستخدام `GET /v1/usage`. يمكن تجميع النتائج حسب النموذج أو المزود وعبر الزمن. قد تكون أعداد الرموز غير مكتملة عندما لا يبلغ المزود عن الاستخدام؛ تحقق من `tokenUsageUnreportedCount`.

استخدم `GET /v1/openapi.json` لمعرفة مسارات API ومعلمات الاستعلام المتاحة. قد تحتوي رسائل الجلسة ومخرجات الأدوات على معلومات حساسة؛ قيّد من يمكنه الوصول إليها والاحتفاظ بها.

<a id="access-activity-data"></a>

### الوصول إلى بيانات النشاط

<Tabs syncKey="hosting" hash={false}>
<Tab title="مستضاف على Cloud">

استخدم لوحة Klex Cloud لمراجعة نشاط البوت والدردشة معه. المستمع المحلي أدناه للبوتات المستضافة ذاتيًا.

</Tab>
<Tab title="مستضاف ذاتيًا">

<a id="access-the-local-admin-api"></a>

لا يعرض التطبيق المستضاف ذاتيًا منفذ Admin API محليًا افتراضيًا. يرتبط المستمع الاختياري بـ `127.0.0.1` و**لا يستخدم المصادقة**. يمكن لأي شخص يصل إليه، بما في ذلك المستخدمون والعمليات المحلية الأخرى، الوصول إلى بيانات البوت الحساسة واستخدام مسارات الإدارة. فعّله فقط حيث يكون هؤلاء المستخدمون والعمليات موثوقين؛ لا تعرضه أو تعيد توجيهه إلى شبكة غير موثوقة.

على سبيل المثال، لبدء بوت headless موجود مع تفعيل المستمع المحلي:

~~~sh
klex --headless --data-dir /path/to/bot --dangerous-local-admin-api-port 2706
~~~

استبدل المسار والمنفذ بالقيم الخاصة بك. من جهاز الكمبيوتر نفسه، يمكنك فحص المسارات المتاحة:

~~~sh
curl http://127.0.0.1:2706/v1/openapi.json
~~~

يمكنك تعيين المنفذ باستخدام `KLEX_DANGEROUS_LOCAL_ADMIN_API_PORT` أيضًا؛ لخيار سطر الأوامر الأولوية. عند الانتهاء، أوقف البوت وأعد تشغيله دون الخيار أو متغير البيئة لتعطيل المستمع.

</Tab>
</Tabs>

لإيقاف بوت أو تغيير وصوله المتصل، راجع [التحكم في بوت Klex](/ar/bot/guides/control-and-limits).
