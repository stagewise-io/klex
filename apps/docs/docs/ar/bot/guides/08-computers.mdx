يمكن لـ Klex Bot استخدام جهاز كمبيوتر متصل للعمل على الملفات وتشغيل الأوامر واستخدام التطبيقات الرسومية عند توفر سطح مكتب. الـ Bot هو العقل والكمبيوتر أداة يستخدمها. يمكن لـ Bot استخدام أكثر من جهاز، ويمكنك إسناد جهاز واحد إلى أكثر من Bot.

اختر جهاز كمبيوتر مُدارًا في Klex Cloud أو وصّل جهازك باستخدام خادم MCP ‏`@klex/machine`. تعتمد الأدوات المتاحة للـ Bot على الجهاز وإعداداته.

<a id="before-you-connect"></a>

## قبل التوصيل

يمنح اتصال الكمبيوتر الـ Bot صلاحيات وصول واسعة. يمكن لـ `@klex/machine` قراءة الملفات وتغييرها وتشغيل أوامر shell بصلاحيات مستخدم نظام التشغيل الذي يشغّله. دليل العمل ليس بيئة معزولة: تظل المسارات المطلقة قابلة للوصول. وقد يكشف سطح المكتب كل ما يستطيع ذلك المستخدم رؤيته أو استخدامه.

استخدم حسابًا مخصصًا محدود الصلاحيات أو جهازًا معزولًا كلما أمكن. أزل بيانات الاعتماد والبيانات الحساسة غير الضرورية، وامنح الوصول فقط للـ Bots والأشخاص الذين تثق بهم. راجع الإجراءات المهمة بشكل مستقل. راجع [التحكم والحدود](/ar/bot/guides/control-and-limits).

<a id="use-a-managed-computer"></a>

## استخدام جهاز مُدار

في قسم **Computers** الخاص بالـ Bot، اختر **Add computer** ثم **Set up a computer**. اختر **Cloud computer** والحجم وإعداد الوصول إلى الإنترنت، وراجع السعر ثم اختر **Create computer**. تحقق من الحالة وأي خطأ اتصال في Cloud: الإسناد وحده لا يضمن اتصال الجهاز.

يمكن للأجهزة المُدارة توفير سطح مكتب للعمل الرسومي بالإضافة إلى أدوات الملفات وshell. عندما تتوفر شاشة يمكنك مشاهدتها في Cloud. يمكن للمسؤول تولّي التحكم ثم إعادته إلى الـ Bot. أثناء تحكم شخص، يُحظر إدخال الـ Bot على سطح المكتب. يتوقف توفر الشاشة والأدوات على توفر الجهاز وتفعيل دعم سطح المكتب.

<a id="connect-your-own-computer-to-cloud"></a>

## توصيل جهازك بـ Cloud

يحتاج الجهاز إلى Node.js 24 أو إصدار أحدث. يمكن لمسؤول المؤسسة إعداد جهاز في Cloud وإسناده إلى Bot مسجّل.

1. في Cloud، افتح قسم **Computers** الخاص بالـ Bot واختر **Add computer** ثم **Set up a computer**.
2. اختر **Your own computer** واتبع تعليمات الإعداد. يوفّر Cloud أمرًا للتثبيت والتسجيل. تعامل مع رمز التسجيل باعتباره سرًا ولا تشاركه في الدردشة أو تضعه في مستودع.
3. شغّل الأمر على الجهاز الذي تريد توصيله. يبدأ التسجيل عملية machine؛ اتركها قيد التشغيل.
4. تحقق من اتصال الجهاز وإسناده إلى الـ Bot. إذا لم يُسند، فأضفه من قسم **Computers** الخاص بالـ Bot. يمكنك إسناد الجهاز نفسه إلى Bots آخرين بشكل منفصل.

تنشئ العملية اتصالًا صادرًا إلى Cloud. يظهر الجهاز غير متصل عندما تتوقف العملية. لا يثبّت التسجيل خدمة في الخلفية: يؤدي إغلاق الطرفية أو إعادة تشغيل الجهاز إلى إيقاف العملية. بعد التسجيل، شغّل `klex-machine` بمستخدم نظام التشغيل نفسه لإعادة تشغيله بهويته المحفوظة. احفظ خصوصية دليل الهوية، وهو افتراضيًا `~/.klex-machine`.

قد يتوفر سطح مكتب متوافق على جهازك أيضًا. في macOS يلزم وجود جلسة مسجّلة الدخول وأذونات تسجيل الشاشة وإمكانية الوصول. في Windows يلزم وجود جلسة تفاعلية مسجّلة الدخول. في Linux يعتمد دعم سطح المكتب على شاشة تعمل وأدوات سطح المكتب المطلوبة. ويمكن لجهاز بلا سطح مكتب توفير أدوات الملفات وshell.

<a id="keep-a-linux-computer-connected"></a>

### إبقاء جهاز Linux متصلًا

يمكن لمسؤول Linux إعداد خدمة systemd لبدء `klex-machine` عند الإقلاع وإعادة تشغيله عند الفشل. يجب تشغيل الخدمة بالمستخدم المحدد محدود الصلاحيات واستخدام هوية machine الموجودة لذلك المستخدم. لا توفّر خدمة الخلفية وحدها جلسة سطح مكتب.

راجع الخدمة قبل تفعيلها. احمِ دليل الهوية وتجنب تشغيل الخدمة بصلاحيات root ما لم يكن لديك سبب محدد.

<a id="connect-locally-without-cloud"></a>

## الاتصال محليًا دون Cloud

لـ Bot مستقل على الجهاز نفسه، شغّل الخادم في الوضع المحلي:

```sh
# ثبّت مرة واحدة باستخدام npm أو pnpm. يلزم Node.js 24 أو أحدث.
npm install -g @klex/machine
klex-machine serve --mode local --cwd /path/to/workspace --port 3123
```

في إعدادات خادم MCP الخاص بالـ Bot، أضف عنوان الخادم المحلي `http://127.0.0.1:3123/mcp`. أبقِ العملية قيد التشغيل أثناء استخدام الـ Bot لها.

الوضع المحلي بلا مصادقة ويستخدم واجهة loopback افتراضيًا. لا تعرض منفذ الاستماع للشبكة: يمكن لأي شخص يصل إليه استخدام الخادم بصلاحيات مستخدم نظام التشغيل. يغيّر `--cwd` دليل البدء، لا حدود الوصول.

<a id="disconnect-a-computer"></a>

## فصل جهاز كمبيوتر

في Cloud، استخدم **Disconnect** على اتصال جهاز الـ Bot لإلغاء إسناده إلى ذلك الـ Bot. يبقى الجهاز في المؤسسة ويحتفظ الـ Bots الآخرون المسند إليهم بإمكانية الوصول. لإيقاف الوصول عبر عملية machine على جهازك، أوقف `klex-machine` وراجع أيضًا الإسنادات في Cloud وبيانات الاعتماد المحلية.
