في معظم التطبيقات المتصلة، يعمل البوت من خلال حسابه الخاص. اضبط أذونات الحساب في التطبيق. امنح البوت الوصول الذي يحتاجه لعمله المكلّف به فقط، وراجعه عند تغير العمل.

<a id="before-connecting-an-app"></a>

## قبل توصيل تطبيق

1. حدد الموارد والإجراءات التي يحتاجها البوت. ابدأ بوصول للقراءة فقط عندما يكون كافيًا.
2. امنح حساب البوت حق الوصول إلى المشاريع أو المجلدات أو المحادثات المعنية بدلًا من المؤسسة بأكملها، عندما يدعم التطبيق هذا النطاق.
3. تحقق مما إذا كان الحساب يستطيع مشاركة البيانات أو تغيير الإعدادات أو حذف الموارد أو تنفيذ إجراءات حساسة أخرى. أزل الأذونات التي لا يحتاج إليها.
4. اختبر سير العمل المقصود ببيانات غير حساسة وراجع النتائج.

كرر هذه المراجعة لكل اتصال، بما في ذلك أجهزة الكمبيوتر المتصلة. يتيح اتصال MCP إمكانات للبوت؛ ويحدد الحساب والبيئة المتصلان نطاق وصول هذه الإمكانات. راجع [الاتصالات](/ar/bot/concepts/brain-and-computers).

<a id="review-and-remove-access"></a>

## مراجعة الوصول وإزالته

راجع الأذونات دوريًا وعند تغير دور البوت. إذا لم يعد الوصول مطلوبًا، فألغِه في التطبيق المتصل وافصل خادم MCP المعني عند الاقتضاء. فصل الخادم وحده لا يلغي أذونات الحساب في التطبيق. عند الاشتباه في حادث، اتبع عملية مؤسستك وفكّر في إيقاف البوت أثناء مراجعة الوصول.

لا يدعم Klex حاليًا الموافقات أو القيود على الإجراءات الفردية. لا تعتمد على المطالبة وحدها لفرض حدود الأذونات؛ استخدم ضوابط الوصول في التطبيق المتصل. راجع [التحكم في بوت Klex](/ar/bot/guides/control-and-limits).
