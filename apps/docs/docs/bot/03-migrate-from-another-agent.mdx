To move a workflow from another agent to Klex, start by recreating its role, connections, and tasks. Do not assume that its configuration, memory, skills, or conversation history will transfer automatically.

## Prepare the workflow

List what the existing agent does, the apps and data it needs, its recurring tasks, and where it reports results. Identify any sensitive permissions and schedules that need special care.

## Set up the Klex Bot

1. [Create a Bot](/bot/quickstart). Describe its purpose, priorities, and preferred style when setting up its [soul](/bot/concepts/soul).
2. [Connect the required apps and computers](/bot/concepts/brain-and-computers) through MCP servers with the capabilities needed for the workflow. Configure the Bot account’s permissions in each connected service.
3. Provide the Bot with the task instructions and relevant context it needs. Review them for accuracy and remove unnecessary secrets. See [Agent Skills](/bot/concepts/agent-skills) for reusable procedures.
4. Set up any recurring work using a suitable connected scheduling service, and check that it can deliver events to the Bot. See [Automate recurring tasks](/bot/guides/recurring-tasks).

## Test before switching over

Run a small, non-sensitive task and compare the result with what you expect. Check permissions, output destinations, and any schedules. Keep an independent review step for high-impact actions; see [Use Klex Bots securely](/guides/secure-bot-usage).

Once the new workflow is working, review and remove any old agent access or schedules that are no longer needed. Platform-specific import and compatibility details need to be checked separately.
