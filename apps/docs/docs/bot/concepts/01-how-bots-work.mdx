> **How do Klex Bots work?**

A Klex Bot manages its memory and active sessions in its own environment. To do work outside that environment, it acts through tools connected to external systems, such as computers and MCP servers. Work happens in those connected environments through the tools available there.

## The Bot and its tools

The Bot's internal environment is where it manages memory and active sessions. Its work tools connect to external environments rather than to the Bot's own internal environment. This keeps the Bot's internal management separate from the systems it uses to carry out work.

For example, a tool connected to a computer can perform work in that computer's environment; an MCP server can provide tools for an external service. The Bot can only act through the tools that are connected to it.

## Manage access

Use the Cloud dashboard to review a Bot's activity and connect or disconnect MCPs. For permissions in other apps and accounts the Bot uses, configure those permissions in the external service or account.

Klex does not currently provide action-by-action approvals or restrictions. To stop a self-hosted Bot, close its app. To stop a Cloud-hosted Bot, select **Stop** in the Cloud dashboard.

See [Hosted vs. self-hosted Klex Bots](/cloud/hosted-vs-local) for hosting options and [Memory](/bot/concepts/memory) for where chats and memory are stored.
