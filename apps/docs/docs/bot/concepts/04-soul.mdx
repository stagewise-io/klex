The soul describes a Bot’s personality, voice, purpose, and priorities. It is separate from its [memory](/bot/concepts/memory) and is included in the context of its regular session.

## Create or update a soul

Use the Bot's Admin API to create or update its soul from instructions. Send `POST /v1/soul` to create a soul from scratch, or `PATCH /v1/soul` to update an existing soul. Use `GET /v1/soul` to read it. See [local Admin API access](/bot/guides/observability#access-the-local-admin-api) for access and security guidance.

Soul generation uses configured chat models and saves the result after it succeeds. For example, instructions might describe the Bot’s job, preferred tone, and approach to decisions. Review the generated soul and update it if needed. Save a soul before sending the Bot new work.

## Storage and access

The soul is stored in the Bot’s [data directory](/bot/concepts/data-directory). The Bot’s Admin API can read the soul and generate a new or updated one from administrator instructions. The regular session does not provide a soul-writing tool.

## If the Bot has no soul

A Bot needs a non-empty soul to handle regular work. Without one, it skips new work and discards the newly added session history; skipped work is not queued. Create a soul before sending new input.
