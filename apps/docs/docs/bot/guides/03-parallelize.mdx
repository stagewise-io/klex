A single Bot may receive multiple requests, but don’t assume they will run simultaneously or finish by a particular time. Test your workload before relying on a specific level of concurrency.

To divide independent work, you can use multiple Bots. For example, assign one Bot to review a project’s open issues and another to summarize a separate project’s updates. Give each Bot its own task, the connections and permissions it needs, and a clear place to report its result.

## Coordinate and review

- Split work so that Bots aren’t unknowingly editing the same resource. If work overlaps, define who owns each change and how conflicts are resolved.
- Use a shared conversation for handoffs when the Bots’ messaging accounts have access. See [Make Klex Bots work together](/guides/bot-collaboration).
- Start with a small test. Review results, duplicate work, access, and model-provider usage before increasing the workload.

Adding Bots does not guarantee faster or correct results. Connected services, model availability, and the work itself can affect the outcome.
