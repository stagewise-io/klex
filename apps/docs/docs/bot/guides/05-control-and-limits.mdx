You can stop a Klex Bot and manage what it can access through its connections and accounts.

## Run a self-hosted Bot without the picker

For Cloud enrollment, obtain an enrollment token from Klex Cloud and make it available to the process as `KLEX_CLOUD_ENROLLMENT_TOKEN` using your approved secret-management process. Then run:

```sh
klex --create-bot
```

Treat the token as a secret: avoid placing it in scripts, command-line arguments, or shell history, and restrict access to the process environment. Add `--headless` to run without the terminal interface.

For a standalone Bot, supply a name instead:

```sh
klex --create-bot --no-cloud --bot-name Ada
```

Configure its provider, model, and connections before expecting it to work. `--create-bot` cannot be combined with `--data-dir` or `KLEX_DATA_DIR`: those identify an existing Bot.

If Cloud enrollment fails, the new Bot directory is retained and its path is printed. With the enrollment token available in `KLEX_CLOUD_ENROLLMENT_TOKEN`, retry with `klex --data-dir PATH`, replacing `PATH` with the printed directory, instead of creating another Bot.

## Stop a Bot

- **Cloud-hosted Bot:** Use **Stop** in the Klex Cloud dashboard.
- **Self-hosted Bot running in the app:** Close the app.

### Stop a headless Bot

On POSIX systems, send `SIGTERM` to the Klex process, or use your service manager’s stop command. If the process is supervised, configure the service so it does not immediately restart the Bot.

For a running headless Bot, the first `SIGTERM` starts a drain: Klex stops accepting new work and waits for current work to become idle before shutting down. The default drain budget is five minutes. It is a limit, not a guarantee that work will finish.

Set `KLEX_DRAIN_TIMEOUT_MS` before starting Klex to change the budget, in milliseconds. Valid values range from `0` to `3600000`; `0` disables the drain. A second `SIGTERM`, or `SIGINT` such as Ctrl+C, skips the remaining drain wait and starts shutdown. If the process is still starting, it shuts down without the running Bot’s drain.

Allow your service manager or orchestrator enough time for both the drain and shutdown cleanup before it forces termination. The default shutdown cleanup timeout is 15 seconds, separate from the drain budget. For example, with the defaults, a Kubernetes `terminationGracePeriodSeconds` of `330` provides a margin beyond both timeouts. Adjust it if you change them. During a drain, the optional readiness probe returns 503. See [Availability](/bot/reliability/availability#monitor-a-self-hosted-bot).

## Manage access

Connect or disconnect a Bot's MCP servers in the Cloud dashboard.

In the self-hosted app, use **Settings → MCP Servers** to inspect, edit, or remove a server; see [MCP and Klex Bots](/bot/concepts/mcp#add-a-remote-server-in-the-self-hosted-app) for the steps and OAuth revocation caveat.

Configure permissions for the accounts and apps the Bot uses directly in those accounts and apps. See [Connections to computers and apps](/bot/concepts/brain-and-computers) for how connections and account permissions relate.

Klex does not currently support approvals or restrictions for individual actions. Configure the Bot's account and app permissions accordingly.

You can also [review the Bot's activity](/bot/guides/observability) in the dashboard.
