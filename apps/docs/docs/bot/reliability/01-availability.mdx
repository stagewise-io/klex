A Klex Bot can be available around the clock while its hosting environment is running. It can be idle between tasks rather than continuously generating responses. New events from a connected MCP server or a one-time reminder can prompt it to resume work.

Availability is not a guarantee that every task will run or succeed. The Bot also needs working model access and the connections required for its task. Event delivery depends on the connected service and MCP server.

For scheduled work, keep the Bot and its connections available when the task is due, and check important results. Use a suitable connected scheduling service for recurring work; internal reminders are one-time. See [Automate recurring tasks](/bot/guides/recurring-tasks).

A self-hosted Bot stops when you close its app. You can stop a Cloud-hosted Bot using the dashboard’s Stop control.
