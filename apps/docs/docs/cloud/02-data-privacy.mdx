A Bot’s chats and memory are stored in its [data directory](/bot/concepts/data-directory). For a Cloud-hosted Bot, that directory is in the hosted environment. For a self-hosted Bot, it is in the environment where you run the Bot. Administrators can access this data through the Bot’s Admin API.

All Cloud-hosted Bot data, including memory, is encrypted in transit and at rest. This statement does not describe encryption for self-hosted Bots; protect your own hosting environment and storage appropriately.

## Access and connected services

A Bot can work with connected apps using the permissions of its accounts. Review the data and actions each account can access, and the policies of connected services and model providers before using sensitive information. See [Use Klex Bots securely](/guides/secure-bot-usage).

This page does not yet establish whether Klex staff can access hosted data, which third parties process it, how credentials are stored, or the retention and deletion terms. Contact Klex for current details before relying on a particular privacy or compliance requirement.

## Analytics and telemetry for a self-hosted Bot

Klex 0.30.1 has two separate reporting systems. The controls below apply to the self-hosted Klex process; they do not describe Cloud-side reporting or connected services.

**Product analytics** are enabled by default in release builds that include an analytics key. Events can include startup and enrollment outcomes, aggregate usage counts, runtime information, and process resource usage. The event schemas do not include chat content or enrollment tokens. Each process uses a temporary random identifier, and the network request exposes the sender’s IP address to the recipient. See the [0.30.1 product analytics details](https://github.com/stagewise-io/klex/blob/baff8a40ce9b896fdd17146dfe9906cefe7c2697/apps/klex/product-analytics.md).

To turn product analytics off, start Klex with `--no-analytics`, or set `KLEX_NO_ANALYTICS=1` or `DO_NOT_TRACK=1` in its environment. The explicit `--analytics` flag overrides the environment opt-out.

**Operational telemetry** is separate. It is off when no telemetry endpoint is configured. Unless telemetry is explicitly disabled, setting an endpoint enables it. The default enabled level includes sensitive operational metadata. The debug level can also export chat content, prompts, and tool payloads. Use only a collector you trust and restrict access to its data. To force telemetry off, use `--disable-telemetry` or `KLEX_DISABLE_TELEMETRY=1`. See the [0.30.1 telemetry details](https://github.com/stagewise-io/klex/blob/baff8a40ce9b896fdd17146dfe9906cefe7c2697/apps/klex/telemetry.md).

Turning off one system does not turn off the other. Neither control disables communication with your configured model providers, MCP servers, or Cloud connection.
