Ein Klex Bot ist ein autonomer Agent mit eigener Identität und eigenem Gedächtnis. Er läuft in einer Bot-Umgebung und arbeitet in anderen Umgebungen, die über MCP (Model Context Protocol) verbunden sind.

Die Bot-Umgebung hält den Bot am Laufen und verwaltet sein Gedächtnis. Seine Arbeit erledigt er in verbundenen Computern und Apps.

<span id="where-the-bot-runs"></span>

## Wo der Bot läuft

Sie können einen in der Cloud gehosteten Bot nutzen oder einen Bot in Ihrer eigenen Umgebung betreiben. Klex empfiehlt Cloud-Hosting. Ein selbst gehosteter Bot kann auch bei Klex Cloud registriert werden. Für einen selbst gehosteten Bot ist die Registrierung bei Klex Cloud technisch nicht erforderlich; ohne sie ist die Nutzung jedoch weniger vollständig. Siehe [Cloud-Hosting und Self-Hosting im Vergleich](/cloud/hosted-vs-local).

<span id="how-the-bot-works-with-computers-and-apps"></span>

## Wie der Bot mit Computern und Apps arbeitet

Ein Bot verbindet sich mit einem MCP-Server, um auf eine externe Umgebung zuzugreifen. Das kann ein vollständiger Computer oder eine App wie GitHub oder Google Workspace sein. Auch ein Computer wird über MCP verbunden.

Bei den meisten MCPs handelt der Bot über ein eigenes Konto oder eine eigene Identität. Diese Identität wird pro Bot eingerichtet und kann Berechtigungen und Zugriffsfreigaben erhalten. Mehr zum Verbindungs- und Zugriffsmodell finden Sie unter [Verbindungen](/bot/concepts/brain-and-computers).

<span id="what-the-bot-remembers"></span>

## Woran sich der Bot erinnert

Das Gedächtnis eines Klex Bots unterstützt Skills und Learnings und kann relevanten Kontext aus früheren Aktivitäten abrufen. Unter [Gedächtnis](/bot/concepts/memory) erfahren Sie, was heute bekannt ist; das [Datenverzeichnis](/bot/concepts/data-directory) erklärt die Speicherung und den Administratorzugriff.
