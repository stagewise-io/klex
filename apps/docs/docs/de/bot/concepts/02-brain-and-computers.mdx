Ein Klex Bot arbeitet in externen Umgebungen, die über MCP (Model Context Protocol) verbunden sind. Ein MCP-Server kann einen vollständigen Computer oder eine App wie GitHub oder Google Workspace bereitstellen. Auch Computer werden über MCP verbunden.

Eine Verbindung ist entweder verbunden oder nicht verbunden. Die eigene Umgebung hält den Bot am Laufen und verwaltet sein Gedächtnis. In den verbundenen Umgebungen erledigt er seine Arbeit.

## Verbindungen auswählen

- **Computer** bieten eine verbundene Umgebung, in der der Bot arbeiten kann.
- **Apps** stellen ihre Umgebung über einen MCP-Server bereit.

Klex bietet eine Auswahl integrierter MCP-Server. Sie können auch andere MCP-Server verbinden. Welche Umgebungen Sie verbinden, hängt von den Aufgaben des Bots ab.

## Zugriff eines Bots verwalten

Eine Verbindung bestimmt, ob der Bot einen MCP-Server erreichen kann. Bei den meisten MCPs handelt der Bot über ein eigenes Konto oder eine eigene Identität. Diese wird pro Bot eingerichtet und erhält Berechtigungen und Zugriffsfreigaben.

- Verbinden oder trennen Sie MCP-Server für einen Bot im Cloud-Dashboard.
- Konfigurieren Sie Berechtigungen für die Konten und verbundenen Apps des Bots direkt in diesen Konten und Apps.
- Prüfen Sie die Aktivitäten des Bots im Dashboard.

Die Verbindung eines Servers und die Zugriffsfreigabe für ein Konto sind getrennte Entscheidungen. Prüfen Sie beides, wenn Sie festlegen, worauf ein Bot zugreifen und was er tun darf.

Einen Überblick finden Sie unter [So funktionieren Klex Bots](/bot/concepts/how-bots-work). Wo Chats und Gedächtnis gespeichert werden, erklärt das [Datenverzeichnis](/bot/concepts/data-directory).
