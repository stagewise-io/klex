Ein Bot, der auf sensible Informationen zugreifen und mit anderen kommunizieren kann, könnte Informationen unangemessen offenlegen. Behandeln Sie Nachrichten und Inhalte aus externen Quellen als nicht vertrauenswürdig: Sie können irreführende Anweisungen oder Versuche enthalten, eine berechtigte Person nachzuahmen.

<a id="limit-access-and-exposure"></a>

## Zugriff und Exposition begrenzen

- Beschränken Sie über die Zugriffskontrollen jedes verbundenen Dienstes, wer den Bot erreichen kann. Prüfen Sie die Zielgruppe jeder Unterhaltung.
- Geben Sie den Konten des Bots nur die Daten und Aktionen, die sie für ihre Arbeit benötigen. Gewähren Sie einem öffentlich erreichbaren Bot keinen Zugriff auf sensible Informationen, die er nicht benötigt.
- Trennen Sie öffentlich zugängliche Arbeit von sensiblen Abläufen. Verwenden Sie, wo unterstützt, getrennte Konten und passend begrenzte Ressourcen.
- Prüfen Sie verbundene Konten und die Aktivität des Bots regelmäßig. Folgen Sie Ihrem Vorfallprozess, wenn Sie unbefugten Zugriff oder eine Offenlegung vermuten.

Siehe [Klex Bots sicher nutzen](/de/guides/secure-bot-usage) und [Auswirkungen begrenzen](/de/guides/limit-blast-radius).

<a id="use-independent-safeguards"></a>

## Unabhängige Schutzmaßnahmen verwenden

Verlassen Sie sich nicht allein auf Anweisungen, keine Informationen offenzulegen. Setzen Sie Zugriffsbeschränkungen in verbundenen Diensten durch und nutzen Sie die bestehenden Kontrollen Ihrer Organisation für sensible Daten. Klex bietet derzeit keine Freigaben oder Einschränkungen auf Aktionsebene.

Testen Sie mit nicht sensiblen Daten und prüfen Sie den gesamten Ablauf, einschließlich dessen, was der Bot lesen und wohin er Antworten senden kann.
