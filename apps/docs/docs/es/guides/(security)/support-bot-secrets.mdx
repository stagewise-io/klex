Un Bot que atiende a clientes solo debe tener acceso a la información y las acciones necesarias para responder a las solicitudes de soporte. No supongas que pedirle que guarde un secreto basta para evitar su divulgación.

<a id="reduce-what-the-bot-can-access"></a>

## Reducir el acceso del Bot

- Evita darle acceso a credenciales de producción, registros sensibles de clientes o documentos internos que no necesite.
- Usa cuentas separadas con permisos limitados para soporte cuando el servicio conectado lo permita. Revisa sus permisos para leer, compartir y modificar datos.
- Mantén las credenciales fuera de las conversaciones y los ejemplos de soporte. Usa el proceso de gestión de credenciales aprobado por tu organización para las integraciones.
- Comprueba quién puede contactar con el Bot y ver sus respuestas en cada servicio conectado.

<a id="review-the-workflow"></a>

## Revisar el flujo de trabajo

Prueba con datos no sensibles, incluidas solicitudes que intenten obtener información fuera del alcance previsto. Revisa los resultados y los permisos en los servicios conectados; no supongas que un Bot rechazará siempre una solicitud maliciosa.

Si una credencial o información sensible puede haberse expuesto, sigue tu proceso de respuesta a incidentes. Revoca o rota las credenciales afectadas y revisa los accesos y la actividad pertinentes. Consulta [Prevenir el robo de información](/es/guides/prevent-information-theft) y [Limitar el alcance de los daños](/es/guides/limit-blast-radius).
