हर Klex बॉट अपनी बातचीत और मेमोरी अपनी डेटा डायरेक्टरी में सहेजता है। क्लाउड-होस्टेड बॉट के लिए यह डायरेक्टरी क्लाउड वातावरण में होती है। सेल्फ़-होस्टेड बॉट के लिए यह उसका डेटा रखने वाले स्थानीय फ़ोल्डर में होती है।

व्यवस्थापक बॉट की Admin API से बातचीत और Skills की समीक्षा कर सकते हैं। Klex Cloud कंसोल प्रत्येक बॉट की Admin API के लिए रिवर्स प्रॉक्सी और फ़्रंटएंड के रूप में काम करता है।

## बॉट का डेटा खोजें और सुरक्षित रखें

<Tabs syncKey="hosting" hash={false}>
<Tab title="क्लाउड-होस्टेड">

बॉट की गतिविधि देखने के लिए उसे Klex Cloud में खोलें। उसकी डेटा डायरेक्टरी होस्ट किए गए वातावरण में होती है। क्लाउड-होस्टेड डेटा की सुरक्षा के बारे में [डेटा गोपनीयता](/cloud/data-privacy) देखें।

</Tab>
<Tab title="सेल्फ़-होस्टेड">

<a id="find-a-self-hosted-bot"></a>
<a id="सेल्फ़-होस्टेड-बॉट-खोजें"></a>

सेल्फ़-होस्टेड Klex ऐप को इंटरैक्टिव रूप से शुरू करने पर डिफ़ॉल्ट रूप से `~/.klex/agents` में बॉट खोजे जाते हैं। `KLEX_HOME` सेट होने पर उस पथ का `agents` फ़ोल्डर इस्तेमाल होता है। `--data-dir` से डायरेक्टरी सीधे चुन सकते हैं; यह विकल्प `KLEX_DATA_DIR` से प्राथमिकता पाता है।

उदाहरण के लिए, ज्ञात डेटा डायरेक्टरी वाला बॉट खोलने के लिए:

```sh
klex --data-dir /path/to/bot
```

उदाहरण के पथ को बॉट की वास्तविक डायरेक्टरी से बदलें। Cloud के बिना बॉट बनाने या उसे हेडलेस चलाने के लिए [स्टैंडअलोन सेटअप गाइड](/bot/guides/standalone-setup) देखें।

<a id="protect-the-data"></a>
<a id="डेटा-सुरक्षित-रखें"></a>

### स्थानीय डायरेक्टरी सुरक्षित रखें

डायरेक्टरी में सेटिंग और क्रेडेंशियल जैसी संवेदनशील जानकारी हो सकती है। ऑपरेटिंग सिस्टम की अनुमतियों से पहुँच सीमित करें और बनाई गई प्रतियों की भी सुरक्षा करें। Unix फ़ाइल मोड वाले सिस्टम पर Klex डायरेक्टरी बनाते समय केवल स्वामी की पहुँच वाली अनुमतियों का अनुरोध करता है; वह मौजूदा डायरेक्टरी की अनुमतियाँ नहीं बदलता। Windows एक्सेस कंट्रोल लिस्ट का उपयोग करता है।

डेटा हटाने या स्थानांतरित करने से पहले अपनी बैकअप और पुनर्स्थापन प्रक्रिया जाँचें।
