[Klex Cloud डैशबोर्ड](https://cloud.klex.bot) में आप देख सकते हैं कि आपका Bot क्या कर रहा है और उससे चैट कर सकते हैं।

एडमिन Bot की Admin API से उसकी चैट और स्किल भी देख सकते हैं। Cloud डैशबोर्ड हर Bot की Admin API के लिए फ्रंटएंड देता है। डेटा कहाँ रखा जाता है, इसके लिए [डेटा डायरेक्टरी](/hi/bot/concepts/data-directory) देखें।

<a id="review-activity-and-diagnostics"></a>

## गतिविधि और डायग्नोस्टिक्स की समीक्षा करें

<Tabs syncKey="hosting" hash={false}>
<Tab title="Cloud पर होस्टेड">

Klex Cloud में अपना Bot खोलें और हाल का काम देखने के लिए **Activity** चुनें। विवरण देखने के लिए कोई गतिविधि चुनें और उपलब्ध होने पर पुरानी गतिविधि देखने के लिए **Load older activity** इस्तेमाल करें। गतिविधि दृश्य में पिछली सभी घटनाएँ न भी हों।

</Tab>
<Tab title="सेल्फ-होस्टेड">

<a id="check-self-hosted-diagnostics"></a>

इंटरैक्टिव Klex ऐप में हाल के रनटाइम लॉग देखने के लिए **Settings → Logs** खोलें। स्क्रॉल करने के लिए ऐरो कुंजियाँ, दिखाए जाने वाले न्यूनतम स्तर को बदलने के लिए `l` और प्रदर्शन शैली बदलने के लिए `v` इस्तेमाल करें। दिखाया गया स्तर बदलने से अतिरिक्त लॉग संग्रह ज़रूरी नहीं कि चालू हो।

व्यूअर मौजूदा प्रक्रिया में कैप्चर की गई अधिकतम 500 प्रविष्टियाँ मेमोरी में रखता है, इसलिए पुरानी प्रविष्टियाँ उपलब्ध न रह सकती हैं। रनटाइम लॉग Bot की बातचीत या कार्य परिणामों का पूरा रिकॉर्ड नहीं हैं। हेडलेस मोड में Klex इंटरैक्टिव व्यूअर की जगह कंसोल में लॉग लिखता है।

वर्ज़न और कनेक्शन विवरण के लिए **Settings → Debug Information** खोलें। इसमें Klex वर्ज़न, डेटा डायरेक्टरी और उपलब्ध होने पर Cloud नामांकन और टनल की स्थिति दिखती है। साझा करने से पहले लॉग और डायग्नोस्टिक्स में संवेदनशील जानकारी जाँचें।

</Tab>
</Tabs>

<a id="if-a-bot-does-not-respond"></a>

## यदि Bot जवाब न दे

Bot से शुरू करके संदेश के स्रोत तक रास्ते का हर हिस्सा जाँचें:

1. **जाँचें कि Bot चल रहा है।** सेल्फ-होस्टेड Bot की प्रक्रिया या सेवा जाँचें। यदि वैकल्पिक हेल्थ लिसनर चालू किया है, तो उसका रेडीनेस एंडपॉइंट जाँचें। सफल जाँच यह साबित नहीं करती कि मॉडल या कनेक्शन काम कर रहे हैं।
2. **मॉडल की पहुँच जाँचें।** पुष्टि करें कि प्रोवाइडर कॉन्फ़िगर है और चैट मॉडल चुना गया है। अनुरोध विफल होने पर प्रोवाइडर का खाता और सेवा जाँचें। [मॉडल](/hi/bot/concepts/models) देखें।
3. **कनेक्शन और खाता जाँचें।** कनेक्टेड ऐप के संदेश के लिए MCP सर्वर की स्थिति, आवश्यक प्राधिकरण और Bot खाते की बातचीत तक पहुँच जाँचें। इवेंट डिलीवरी सर्वर की क्षमताओं पर भी निर्भर करती है। [MCP और Klex Bots](/hi/bot/concepts/mcp#if-a-connection-needs-attention) देखें।
4. **उपलब्ध गतिविधि और लॉग देखें।** अनुरोध के समय के आसपास त्रुटियाँ खोजें। उपलब्ध होने पर Cloud डैशबोर्ड या ऊपर दिए सेल्फ-होस्टेड डायग्नोस्टिक्स इस्तेमाल करें। लॉग और गतिविधि अधूरे हो सकते हैं; केवल प्रविष्टि न होने से डिलीवरी की विफलता का स्थान तय नहीं होता।

साझा करने से पहले डायग्नोस्टिक्स में संवेदनशील जानकारी जाँचें। सहायता अनुरोध में क्रेडेंशियल शामिल न करें।

<a id="review-activity-with-the-admin-api"></a>

## Admin API से गतिविधि की समीक्षा करें

Admin API इस्तेमाल करने वाले एडमिन यह कर सकते हैं:

- `GET /v1/sessions` से स्थायी सत्र इंस्टेंस सूचीबद्ध करें, फिर `GET /v1/sessions/{instanceId}/messages` से सत्र के संदेश प्राप्त करें। पुराने पेज लाने के लिए `nextCursor` का पालन करें। कुछ पुराने संदेश काटे गए हो सकते हैं; `trimmedMessageCount` जाँचें।
- `GET /v1/introspect/sessions` से लाइव सत्र गतिविधि देखें। सत्र जानकारी में `childSessions` शामिल हो सकते हैं, जैसे सक्रिय मेमोरी प्राप्ति, मेमोरी लेखन या परामर्श सत्र। समाप्त चाइल्ड सत्र छोड़ दिए जाते हैं, इसलिए यह पूरा इतिहास नहीं है।
- `GET /v1/usage` से दर्ज मॉडल-कॉल उपयोग पूछें। परिणाम मॉडल या प्रोवाइडर के अनुसार समूहित और समय के साथ एकत्र किए जा सकते हैं। प्रोवाइडर उपयोग रिपोर्ट न करे तो टोकन कुल अधूरे हो सकते हैं; `tokenUsageUnreportedCount` जाँचें।

API के उपलब्ध रूट और क्वेरी पैरामीटर के लिए `GET /v1/openapi.json` इस्तेमाल करें। सत्र संदेशों और टूल आउटपुट में संवेदनशील जानकारी हो सकती है; उन्हें एक्सेस और सुरक्षित रखने वालों को सीमित करें।

<a id="access-activity-data"></a>

### गतिविधि डेटा एक्सेस करें

<Tabs syncKey="hosting" hash={false}>
<Tab title="Cloud पर होस्टेड">

Bot की गतिविधि देखने और उससे चैट करने के लिए Klex Cloud डैशबोर्ड इस्तेमाल करें। नीचे दिया स्थानीय लिसनर सेल्फ-होस्टेड Bot के लिए है।

</Tab>
<Tab title="सेल्फ-होस्टेड">

<a id="access-the-local-admin-api"></a>

सेल्फ-होस्टेड ऐप डिफ़ॉल्ट रूप से स्थानीय Admin API पोर्ट नहीं खोलता। इसका वैकल्पिक लिसनर `127.0.0.1` से बँधा है और इसमें **ऑथेंटिकेशन नहीं है**। अन्य स्थानीय उपयोगकर्ताओं और प्रक्रियाओं सहित जो भी उस तक पहुँच सकता है, वह संवेदनशील Bot डेटा एक्सेस कर सकता है और प्रबंधन रूट इस्तेमाल कर सकता है। इसे केवल वहाँ चालू करें जहाँ वे उपयोगकर्ता और प्रक्रियाएँ विश्वसनीय हों; इसे अविश्वसनीय नेटवर्क पर उजागर या फ़ॉरवर्ड न करें।

उदाहरण के लिए, मौजूदा हेडलेस Bot को स्थानीय लिसनर चालू करके शुरू करने के लिए:

~~~sh
klex --headless --data-dir /path/to/bot --dangerous-local-admin-api-port 2706
~~~

पथ और पोर्ट अपने मानों से बदलें। उसी कंप्यूटर से उपलब्ध रूट देख सकते हैं:

~~~sh
curl http://127.0.0.1:2706/v1/openapi.json
~~~

पोर्ट `KLEX_DANGEROUS_LOCAL_ADMIN_API_PORT` से भी सेट कर सकते हैं; कमांड-लाइन विकल्प को प्राथमिकता मिलती है। पूरा होने पर Bot रोकें और लिसनर बंद करने के लिए विकल्प या एनवायरनमेंट वैरिएबल के बिना फिर शुरू करें।

</Tab>
</Tabs>

Bot रोकने या उसकी कनेक्टेड पहुँच बदलने के लिए [अपना Klex Bot नियंत्रित करें](/hi/bot/guides/control-and-limits) देखें।
