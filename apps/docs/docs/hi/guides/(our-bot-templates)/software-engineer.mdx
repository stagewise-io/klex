Software Engineer टेम्पलेट Klex Bot को टिकट से लेकर मर्ज हुए पुल रिक्वेस्ट तक इंजीनियरिंग काम संभालने के लिए कॉन्फ़िगर करता है। Bot कनेक्ट किए गए कंप्यूटर पर Claude Code या Codex CLI जैसे कोडिंग एजेंटों की CLI चलाता है, उनका लिखा सब कुछ जाँचता है और पुल रिक्वेस्ट, CI, टिकट तथा टीम अपडेट खुद संभालता है। वह हाथ से कोड तभी लिखता है जब बदलाव कुछ ही पंक्तियों का हो और निर्देश लिखने से तेज़ हो।

<Panel title="ध्यान दें">
Bot टेम्पलेट [Klex Cloud](https://cloud.klex.bot) में प्रबंधित होते हैं। अगर आप Klex Cloud के बिना Klex स्वयं होस्ट करते हैं, तो MCP से कंप्यूटर कनेक्ट करके और Bot की डेटा डायरेक्टरी में समान Agent Skills जोड़कर यही कार्यप्रवाह अपना सकते हैं।
</Panel>

## रोज़मर्रा का काम

Software Engineer Bot वही चक्र अपनाता है जो कोई मानव इंजीनियर कोडिंग एजेंटों को निर्देशित करते समय अपनाता है।

1. **टिकट पढ़ें और दायरा स्पष्ट करें।** Bot Linear, Jira या GitHub Issues में टिकट, संबंधित कोड और हाल का Git इतिहास पढ़ता है। लक्ष्य या स्वीकृति मानदंड स्पष्ट न हों तो शुरू करने से पहले अनुरोधकर्ता से पूछता है।
2. **हर काम को worktree और टर्मिनल सेशन में अलग रखें।** Bot हर काम के लिए Git worktree और ब्रांच बनाता है, उदाहरण के लिए `git worktree add ../repo-task-a -b task-a origin/main` से, और एजेंट को नाम वाले `tmux` सेशन में चलाता है। worktree सौंपने से पहले वह निर्भरताएँ इंस्टॉल करता है और टेस्ट चलने की पुष्टि करता है। अधिकतर टिकटों पर एक एजेंट चलता है; कई स्वतंत्र कामों पर दो से चार एजेंट समानांतर चल सकते हैं और Bot हर ब्रांच का हिसाब रखता है।
3. **ठोस निर्देश लिखें और निगरानी करें।** हर एजेंट को लक्ष्य, जाँचने वाली फ़ाइलें या टिकट, सीमाएँ और टेस्ट, lint व टाइप जाँच के सटीक कमांड मिलते हैं। Bot चलते सेशन देखता है, अटकने पर लक्षित निर्देश भेजता है या लूप में फँसे एजेंट को रोककर निर्देश फिर लिखता है।
4. **PR खोलने से पहले परिणाम जाँचें।** एजेंट कभी बिना सत्यापन के काम पास होने की रिपोर्ट करते हैं, इसलिए Bot पूरा `git diff origin/main...HEAD` पढ़ता है। वह खुद टेस्ट, lint और टाइप जाँच चलाता है, उपयोगकर्ता को दिखने वाला व्यवहार देखता है और कमज़ोर किए गए टेस्ट, गढ़े हुए API, दबाई गई त्रुटियाँ, दोहराए गए हेल्पर और बचे हुए अस्थायी फ़ाइलें खोजता है। समस्या मिलने पर वह फ़ाइल और पंक्ति सहित क्रमांकित सुधार भेजता है या दो चक्रों में प्रगति न होने पर खुद ठीक करता है। काम एकीकृत होने पर `git worktree remove` से अनुपयोगी worktree हटाता है।
5. **CI और समीक्षा के दौरान पुल रिक्वेस्ट संभालें।** Bot रिपॉज़िटरी के ब्रांच, कमिट और PR नियमों के अनुसार केंद्रित PR खोलता है और ऐसे समीक्षक के लिए विवरण लिखता है जिसने टिकट नहीं पढ़ा। हर push के बाद CI देखता है, विफलता लॉग पढ़ता है, समस्या स्थानीय रूप से दोहराता है और कारण ठीक करता है। वह लोगों और समीक्षा बॉट की हर टिप्पणी का जवाब देता है; ज़रूरी जाँच और अनुमोदन पूरे होने तथा अनुमति होने पर ही मर्ज करता है। वह डिप्लॉय जाँचता है, टिकट अपडेट करता है और चैट में स्थिति बताता है।
6. **टीम के पुल रिक्वेस्ट की समीक्षा करें।** अनुरोध पर Bot संबंधित टिकट और पूरा diff पढ़ता है। वह इसी क्रम में शुद्धता, सुरक्षा, डिज़ाइन, टेस्ट और पठनीयता जाँचता है; रोकने वाली समस्याओं को वैकल्पिक सुझावों से अलग करता है और केवल सत्यापित निष्कर्ष पोस्ट करता है।

## टेम्पलेट में क्या है

[Klex Cloud](https://cloud.klex.bot) में Software Engineer टेम्पलेट Bot की soul, डिफ़ॉल्ट सेटिंग, प्रबंधित skills, टूल श्रेणियाँ और पहली बार की ऑनबोर्डिंग सूची तय करता है।

### Skills

Bot के हर कनेक्शन पर Klex Cloud इन skills को Bot के `templates` नेमस्पेस में सिंक करने की कोशिश करता है। इसके लिए template skills समर्थित Bot संस्करण चाहिए और सिंक विफल हो सकता है।

| Skill | काम |
| --- | --- |
| `set-up-coding-agents` | टीम द्वारा भुगतान की गई कोडिंग एजेंट CLI चुनता है, आधिकारिक दस्तावेज़ के अनुसार कनेक्टेड या प्रबंधित कंप्यूटर पर इंस्टॉल करता है और चैट में रहस्य माँगे बिना ब्राउज़र साइन-इन में मदद करता है। |
| `delegate-to-coding-agents` | टिकट की योजना बनाता है, अलग Git worktree और नाम वाले `tmux` सेशन तैयार करता है, एजेंटों को निर्देश देता है, समानांतर काम की निगरानी करता है और पूरे हुए worktree हटाता है। |
| `review-agent-work` | पूरा diff पढ़ता है, जाँच खुद चलाता है, सामान्य गलतियाँ पकड़ता है, ठोस सुधार भेजता है और PR से पहले कमिट व्यवस्थित करता है। |
| `own-pull-requests` | केंद्रित PR खोलता है, CI सफल रखता है, समीक्षा का जवाब देता है और मर्ज तथा डिप्लॉय तक काम देखता है। |
| `review-pull-requests` | टीम के PR में शुद्धता, सुरक्षा, डिज़ाइन, टेस्ट और पठनीयता जाँचता है और बाधाओं को वैकल्पिक सुझावों से अलग करता है। |
| `connect-your-tools` | टेम्पलेट की टूल श्रेणियाँ बताता है ताकि Bot उपयोगी टूल समझे और Klex Cloud कनेक्टर या कस्टम MCP सर्वर से जोड़ने का सुझाव दे सके। |

### टूल श्रेणियाँ

आप टीम के मौजूदा टूल Klex Cloud कनेक्टर या कस्टम MCP सर्वर से जोड़ सकते हैं।

- **सोर्स नियंत्रण।** GitHub, GitLab, Bitbucket.
- **टिकट ट्रैकिंग।** Linear, Jira, GitHub Issues.
- **CI।** GitHub Actions, Vercel, CircleCI, Buildkite.
- **दस्तावेज़ और ज्ञान।** Notion, Confluence, Google Docs.
- **चैट।** Slack, Teams, Discord.
- **अन्य टूल।** Sentry, PostHog, Figma, क्लाउड कंसोल या MCP के माध्यम से डेटाबेस।

### डिफ़ॉल्ट और ऑनबोर्डिंग सूची

डिफ़ॉल्ट रूप से टेम्पलेट शक्तिशाली मॉडल स्तर उपयोग करता है, आपका अपना कंप्यूटर कनेक्ट न होने पर मध्यम क्लाउड कंप्यूटर सुझाता है और `test-first` तथा `small-prs` गुण चालू करता है। आप `nitpicker` और `boy-scout` भी चालू कर सकते हैं।

Cloud Bot के कनेक्ट होने पर ये शुरुआती कार्य जोड़ने की कोशिश करता है। इसके लिए Bot में todos API का समर्थन ज़रूरी है:

1. उपयोग होने वाली रिपॉज़िटरी, टिकट ट्रैकर और CI पहचानें और हर एक तक पहुँच जाँचें।
2. टीम के कोडिंग एजेंट, जैसे Claude Code, Codex या Cursor, की पुष्टि करें और उन तक पहुँच वाला कंप्यूटर कनेक्ट करें।
3. मुख्य संचार चैनल तय करें, जैसे Cloud चैट, Slack या Teams।
4. टीम के PR नियम जानें: ब्रांच नाम, आवश्यक समीक्षाएँ और जाँच, और मर्ज करने वाला व्यक्ति।
5. पहला टिकट या काम चुनें।

## अच्छी प्रक्रियाएँ

- **Bot को अपने खाते दें।** GitHub, Linear और Slack के लिए अलग पहचान बनाएँ ताकि अनुमतियाँ सीमित रहें और हर कमिट, टिप्पणी और स्थिति परिवर्तन का पता चले। [अलग पहचान बनाएँ](/hi/guides/bot-identities) देखें।
- **इंजीनियरिंग संदर्भ साझा करें।** Bot को कंपनी हैंडबुक, आर्किटेक्चर दस्तावेज़ और रिपॉज़िटरी योगदान गाइड तक पहुँच दें। [कंपनी हैंडबुक बनाएँ](/hi/guides/company-handbook) देखें।
- **Bots के बीच काम सौंपने के लिए साझा चैनल उपयोग करें।** अगर Product Manager Bot टिकट बनाता है और Software Engineer Bot उन्हें लागू करता है, तो उन्हें `#bot-communication` जैसे ऐसे चैनल में रखें जिसे लोग भी पढ़ सकें। [साझा मैसेजिंग बोर्ड उपयोग करें](/hi/guides/shared-messaging-boards) देखें।
- **कोडिंग CLI के लिए API कुंजी से बेहतर सदस्यता चुनें।** API कुंजी से हर टोकन का भुगतान करने के बजाय ब्राउज़र लॉगिन से टीम सदस्यता में CLI साइन इन करें। रहस्य चैट, टिकट और रिपॉज़िटरी से दूर रखें। अगर प्रदाता केवल API कुंजी देता है, तो कुंजी सीधे कंप्यूटर पर सेट करें।
- **मर्ज के नियम जल्दी तय करें।** तय करें कि जाँच और अनुमोदन के बाद Bot अपने PR मर्ज कर सकता है या हमेशा कोई व्यक्ति मर्ज करेगा। जब तक टेस्ट कमांड और PR समीक्षा प्रक्रिया टीम की अपेक्षा से मेल न खाएँ, छोटे और स्पष्ट दायरे वाले टिकटों से शुरुआत करें।
