既存エージェントの仕事と役立つ知識を Klex Bot に引き継ぎます。まず、何をしているか、何を知っているか、どのリソースを使っているかを集めます。

<a id="prepare-the-workflow"></a>

## 必要な情報を集める

現在のエージェントに引き継ぎ文書を依頼します。以下のプロンプトを出発点として、移行したい仕事に合わせて調整してください。

~~~text
あなたの仕事を新しい AI エージェントに移行します。新しいエージェントとその管理者が仕事を続けるために使える引き継ぎ文書を 1 つ作成してください。

明確な見出しと実用的な詳細を使い、次の内容を含めてください。

1. 役割と優先事項: 目的、責任、望ましい働き方、一緒に働く人やチーム。
2. 知識と背景: 学んだ重要な事実、用語、決定、好み、関連する背景。根拠となる情報の所在を示してください。
3. 日課と予定: 定期タスク、時刻とタイムゾーン、トリガー、期待する成果、結果の送付先。
4. 典型的な手順: 段階的なワークフロー、判断点、引き継ぎ、例、結果の確認方法。
5. スキルと学び: 再利用できる手順、過去の仕事から得た教訓、よくある問題と対処法。
6. 接続とアクセス: 各ワークフローに必要なアプリ、アカウント、リソース、機能。認証情報を含めずに必要なアクセスを説明してください。
7. 未完了の仕事: 現在のタスク、保留中の決定、期限、それぞれの次の行動。

利用できる情報を使ってください。アクセスできないことや不確かなことは推測せず明記してください。パスワード、トークン、API キー、その他の秘密情報は含めないでください。共有内容を私が判断できるよう機密情報を示してください。引き継ぎを 1 つの構造化文書として返してください。
~~~

文書の正確性と機密情報を確認します。以前のエージェントがアクセスできなかった、別の場所に保存された予定や指示などを追加します。

<a id="set-up-your-klex-bot"></a>

## Klex Bot を設定する

1. [Klex Bot を作成](/ja/bot/quickstart)します。引き継ぎ文書を使って仕事と性格を説明します。
2. 引き継ぎの関連内容を Bot に渡し、担当する仕事を伝えます。再利用できる手順には [Agent Skills](/ja/bot/concepts/agent-skills) を使います。
3. 仕事に必要な[アプリとコンピューターを接続](/ja/bot/concepts/brain-and-computers)し、各サービスで Bot アカウントのアクセスを設定します。
4. 接続したスケジュールサービスで定期的な仕事を設定します。[定期タスクを自動化する](/ja/bot/guides/recurring-tasks)を参照してください。

<a id="test-before-switching-over"></a>

## 引き継ぎを確認する

代表的なタスクを試し、結果を確認します。Bot がリソースにアクセスでき、適切な場所に報告し、予定された仕事を受け取れることを確認します。新しいワークフローが動作したら、不要になった旧エージェントのアクセスと予定を削除します。
