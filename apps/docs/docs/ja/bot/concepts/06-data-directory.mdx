各 Klex ボットは、会話と記憶を独自のデータディレクトリに保存します。クラウドホストのボットでは、このディレクトリはクラウド環境にあります。セルフホストのボットでは、そのデータを保存するローカルフォルダーにあります。

管理者は、ボットの Admin API を通じて会話と Skills を確認できます。Klex Cloud コンソールは、各ボットの Admin API のリバースプロキシとフロントエンドとして機能します。

## ボットのデータを探して保護する

<Tabs syncKey="hosting" hash={false}>
<Tab title="クラウドホスト">

Klex Cloud でボットを開くと、アクティビティを確認できます。データディレクトリはホスト環境にあります。クラウド上のデータの保護については、[データプライバシー](/cloud/data-privacy)を参照してください。

</Tab>
<Tab title="セルフホスト">

<a id="find-a-self-hosted-bot"></a>
<a id="セルフホストのボットを探す"></a>

セルフホストの Klex アプリの対話型起動では、デフォルトで `~/.klex/agents` 内のボットを探します。`KLEX_HOME` が設定されている場合は、そのパス内の `agents` フォルダーを使用します。`--data-dir` でディレクトリを直接指定することもできます。このオプションは `KLEX_DATA_DIR` より優先されます。

例えば、データディレクトリが分かっているボットを開くには、次を実行します。

```sh
klex --data-dir /path/to/bot
```

例のパスをボットの実際のディレクトリに置き換えてください。Cloud を使わずにボットを作成する方法や、ヘッドレスで実行する方法は、[スタンドアロン設定ガイド](/bot/guides/standalone-setup)を参照してください。

<a id="protect-the-data"></a>
<a id="データを保護する"></a>

### ローカルディレクトリを保護する

ディレクトリには、設定や認証情報などの機密情報が含まれる場合があります。OS の権限でアクセスを制限し、作成したコピーも保護してください。Unix ファイルモードを使用するシステムでは、Klex はディレクトリの作成時に所有者のみがアクセスできる権限を要求します。既存のディレクトリの権限は変更しません。Windows はアクセス制御リストを使用します。

データを削除・移動する前に、バックアップと復元の手順を確認してください。
