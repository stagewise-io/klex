繰り返し作業には、Bot にイベントを届けられる接続済みのカレンダーまたはスケジュールサービスを使います。サービスは必要なスケジュールに対応し、MCP 接続を通じて必要な機能を提供する必要があります。

<a id="set-up-a-routine"></a>

## 定期的な作業を設定する

1. スケジュールサービスを接続し、Bot のアカウントを認可します。Bot がスケジュールを作成し、イベントを受信できることを確認します。
2. Bot に作業内容、頻度、タイムゾーン、結果の送信先を伝えます。必要なアプリやデータへのアクセスを許可します。
3. Bot にスケジュールの作成を依頼し、サービス上で確認します。実際に使う前にワークフローをテストし、結果を確認します。

例：「毎週月曜 09:00 Europe/Berlin に、プロジェクトの未解決 issue を要約し、プロジェクトのチャンネルに投稿して」。Bot には動作するスケジュールに加え、issue の取得元と投稿先チャンネルへのアクセスが必要です。

<a id="reminders-and-learned-procedures"></a>

## リマインダーと学習した手順

Bot は短期的な作業や一回限りのリマインダーに内部の to-do を使えます。これは繰り返し用のカレンダーではありません。定期的なスケジュールには適切な接続済みサービスを使ってください。

管理者は `GET` と `POST /v1/todos` で to-do を一覧・作成し、`PATCH` または `DELETE /v1/todos/{id}` で更新・削除できます。リストは Bot のセッション間で共有され、変更は次のステップで反映されます。リマインダー時刻は未来で、UTC オフセットまたは `Z` を含める必要があります。ルートの利用可否は Bot の OpenAPI ドキュメントで確認してください。セルフホストの Bot については、[ローカル Admin API へのアクセス](/ja/bot/guides/observability#access-the-local-admin-api)とセキュリティ上の制限を参照してください。

Bot は経験から再利用可能な手順を [Agent Skill](/ja/bot/concepts/agent-skills) として学習することもでき、慣れた作業の実行に役立ちます。

予定時刻に Bot と接続先が利用可能な状態を保ち、重要な結果には通常の監視またはエスカレーションの手順を使ってください。
