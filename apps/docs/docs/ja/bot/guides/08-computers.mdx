Klex Bot は接続されたコンピューターでファイルを扱い、コマンドを実行し、デスクトップが利用できる場合はグラフィカルなアプリを使えます。Bot が頭脳で、コンピューターはその道具です。1 つの Bot が複数のコンピューターを使うことも、1 台を複数の Bot に割り当てることもできます。

Klex Cloud で管理対象のコンピューターを選ぶか、MCP サーバー `@klex/machine` を使って自分のコンピューターを接続します。Bot が使えるツールは、コンピューターとその設定によって異なります。

<a id="before-you-connect"></a>

## 接続する前に

コンピューターを接続すると、Bot に広範なアクセス権が与えられます。`@klex/machine` は実行する OS ユーザーの権限でファイルの読み書きや shell コマンドの実行ができます。作業ディレクトリはサンドボックスではなく、絶対パスにもアクセスできます。デスクトップからは、そのユーザーが閲覧または使用できるものが公開される可能性があります。

可能であれば、権限を制限した専用アカウントか、隔離されたコンピューターを使ってください。不要な認証情報や機密データを取り除き、信頼できる Bot と人にのみアクセスを許可します。重要な操作は別途確認してください。[制御と制限](/ja/bot/guides/control-and-limits)も参照してください。

<a id="use-a-managed-computer"></a>

## 管理対象のコンピューターを使う

Bot の **Computers** セクションで **Add computer**、**Set up a computer** の順に選びます。**Cloud computer** を選び、サイズとインターネットアクセスの設定を指定し、料金を確認して **Create computer** を選びます。Cloud で状態と接続エラーを確認してください。割り当てだけでは接続を保証しません。

管理対象のコンピューターは、ファイルや shell のツールに加え、グラフィカルな作業用のデスクトップを提供できます。画面が利用できる場合は Cloud で表示できます。管理者は制御を引き継ぎ、その後 Bot に戻せます。人が制御している間、Bot のデスクトップへの入力はブロックされます。画面とツールは、コンピューターが利用可能でデスクトップのサポートが有効な場合に利用できます。

<a id="connect-your-own-computer-to-cloud"></a>

## 自分のコンピューターを Cloud に接続する

コンピューターに Node.js 24 以降が必要です。組織の管理者は Cloud でコンピューターを設定し、登録済みの Bot に割り当てることができます。

1. Cloud で Bot の **Computers** セクションを開き、**Add computer**、**Set up a computer** の順に選びます。
2. **Your own computer** を選び、セットアップ手順に従います。Cloud はインストールと登録用のコマンドを提供します。登録コードは秘密情報として扱い、チャットで共有したりリポジトリにコミットしたりしないでください。
3. 接続したいコンピューターでコマンドを実行します。登録によって machine プロセスが起動するので、実行したままにします。
4. コンピューターが接続され、Bot に割り当てられていることを確認します。割り当てられていなければ、Bot の **Computers** セクションから追加します。同じコンピューターを別の Bot に個別に割り当てることもできます。

プロセスは Cloud に向けて外向きに接続します。プロセスが停止すると、コンピューターはオフラインと表示されます。登録によってバックグラウンドサービスはインストールされません。ターミナルを閉じるかコンピューターを再起動するとプロセスは停止します。登録後は同じ OS ユーザーとして `klex-machine` を実行すると、保存された識別情報で再起動できます。識別情報のディレクトリ（既定では `~/.klex-machine`）は非公開にしてください。

自分のコンピューターでも対応するデスクトップを利用できる場合があります。macOS ではログイン済みのセッションと、画面収録およびアクセシビリティの権限が必要です。Windows ではログイン済みの対話型セッションが必要です。Linux では動作するディスプレイと必要なデスクトップツールに依存します。デスクトップのないコンピューターでも、ファイルと shell のツールは利用できます。

<a id="keep-a-linux-computer-connected"></a>

### Linux コンピューターの接続を維持する

Linux の管理者は、起動時に `klex-machine` を開始し、障害時に再起動する systemd サービスを設定できます。サービスは意図した非特権ユーザーで実行し、そのユーザーの既存の machine 識別情報を使用する必要があります。バックグラウンドサービスだけではデスクトップセッションは提供されません。

有効にする前にサービスを確認してください。識別情報のディレクトリを保護し、具体的な理由がない限り root で実行しないでください。

<a id="connect-locally-without-cloud"></a>

## Cloud を使わずローカルで接続する

同じコンピューター上のスタンドアロン Bot では、サーバーをローカルモードで実行します。

```sh
# npm または pnpm で一度インストールします。Node.js 24 以降が必要です。
npm install -g @klex/machine
klex-machine serve --mode local --cwd /path/to/workspace --port 3123
```

Bot の MCP サーバー設定にローカルサーバーの URL `http://127.0.0.1:3123/mcp` を追加します。Bot が使用している間はプロセスを実行したままにしてください。

ローカルモードには認証がなく、既定で loopback インターフェースを使います。待ち受けをネットワークに公開しないでください。到達できる人は誰でも OS ユーザーの権限でサーバーを利用できます。`--cwd` は開始ディレクトリを変更しますが、アクセス範囲は制限しません。

<a id="disconnect-a-computer"></a>

## コンピューターの接続を解除する

Cloud で Bot のコンピューター接続にある **Disconnect** を使うと、その Bot への割り当てを取り消せます。コンピューターは組織に残り、他の割り当て済み Bot は引き続きアクセスできます。自分のコンピューターの machine プロセスを通じたアクセスを止めるには `klex-machine` を停止し、Cloud の割り当てとローカル認証情報も確認してください。
