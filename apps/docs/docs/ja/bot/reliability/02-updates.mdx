<a id="monitor-a-self-hosted-bot"></a>

Klex をアップデートするとき、通常は新しい Bot を作成する必要はありません。Bot の設定、チャット、メモリは、その [データディレクトリ](/bot/concepts/data-directory)に関連付けられています。

## Bot のアップデートと保護

<Tabs syncKey="hosting" hash={false}>
<Tab title="クラウドホスト">

Klex Cloud は、クラウドホスト Bot の実行環境を管理します。変更後はダッシュボードで Bot を開き、状態とアクティビティを確認してください。Cloud のデータについては、[データとプライバシー](/cloud/data-privacy)を参照してください。

</Tab>
<Tab title="セルフホスト">

<a id="update-a-self-hosted-installation"></a>

アップデート前にリリースノートを読み、そのバージョン固有の手順を確認してください。アップデート後は、Bot が起動し、接続が機能し、重要なワークフローが引き続き期待どおりの結果を出すことを確認してください。Klex は起動時に対応するローカルデータを確認し、必要に応じて移行します。

インストーラーが管理するインストールでは、対話型アプリに利用可能なアップデートが表示されることがあります。アップデートのバナーで `u` を押すと、インストールして再起動します。セッションが実行中の場合、アプリは中断を警告し、もう一度 `u` を押すよう求めます。

自動アップデートはデフォルトで無効です。管理対象のインストールで有効にするには、`--auto-update` を指定して Klex を起動するか、`KLEX_AUTO_UPDATE=1` を設定します。環境変数の設定を上書きして無効にするには、`--no-auto-update` を使います。これは対話型モードとヘッドレスモードの両方で動作します。他のインストール方式では、このアップデーターは使用されません。

Klex は Bot の起動前と実行中に定期的にアップデートを確認します。実行中にアップデートがインストールされると、新しい作業を一時停止し、現在の作業を待ってから再起動します。待機には、作業中の時間として 10 分の上限があります。リアルタイム通話が進行中の場合はタイマーが一時停止します。時間内に完了しない作業は中断されることがあります。すべてのタスクが完了したと決めつけず、アップデート後にログと Bot を確認してください。

<a id="protect-self-hosted-data"></a>

### データをバックアップする

手動アップデートの前に、[セルフホスト Bot を停止し](/bot/guides/control-and-limits#stop-a-bot)、データディレクトリの安全なバックアップを作成してください。自動アップデートが無効な場合は、インストーラーが管理する対話型インストールを再起動し、アップデートバナーを使います。自動アップデートを有効にする場合は、代わりに Bot を停止した状態で定期的にバックアップする計画を立ててください。ディレクトリには機密情報が含まれることがあるため、バックアップへのアクセスを制限してください。組織のバックアップと復旧の手順に従ってください。

アップデート済みのデータディレクトリを古いバージョンの Klex で開くことは、互換性を確認するまで避けてください。アップデートに失敗した場合は、報告されたエラーを調べ、Bot のデータを変更または削除する前に、リリースノートまたは Klex サポートに確認してください。
