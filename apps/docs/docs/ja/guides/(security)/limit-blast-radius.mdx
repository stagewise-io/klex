Bot のアカウントと接続環境のアクセスを制限して、侵害された Bot による影響を抑えます。適切な境界は、関係するアプリ、コンピューター、データによって異なります。Bot への指示だけではアクセス制御になりません。

<a id="reduce-exposure"></a>

## 露出を減らす

- 接続アプリが対応している場合は、Bot に専用アカウントを使います。業務に必要なリソースと権限だけを与えます。
- 機密リソースを一般的な作業から分離します。Bot に必要でない限り、本番システムや機密データを接続しないでください。
- 各サービスのアクセス制御を使い、Bot や Bot が使う会話やツールにアクセスできる人を制限します。
- 情報の共有、設定の変更、破壊的操作の権限を確認します。影響の大きい変更には別の承認手順を使います。
- 定期的にアクセスを見直し、不要になった接続と付与権限を削除します。

アカウント権限のチェックリストは[Klex Bot を安全に使う](/ja/guides/secure-bot-usage)を参照してください。

<a id="prepare-to-respond"></a>

## 対応に備える

インシデントが起きる前に、Bot が使うアカウント、接続、環境を把握します。侵害が疑われる場合は、インシデント対応手順に従い、Bot の停止、接続先サービスのアクセス取り消し、影響を受けた認証情報の更新、関連活動の確認を検討します。Bot を停止するだけでは、アクセスの取り消しや実行済み操作の調査の代わりにはなりません。
