ほとんどの接続アプリでは、Bot は自分のアカウントを通じて行動します。そのアカウントの権限をアプリで設定してください。Bot には担当業務に必要なアクセスだけを与え、業務が変わったら見直します。

<a id="before-connecting-an-app"></a>

## アプリを接続する前に

1. Bot に必要なリソースと操作を特定します。読み取り専用で十分なら、そこから始めます。
2. アプリが対応する場合、Bot のアカウントには組織全体ではなく、該当するプロジェクト、フォルダー、会話へのアクセスを与えます。
3. アカウントがデータの共有、設定の変更、リソースの削除、その他の機密性の高い操作を実行できるか確認します。不要な権限は削除します。
4. 想定するワークフローを機密性のないデータでテストし、結果を確認します。

接続されたコンピューターを含め、接続ごとにこの確認を繰り返します。MCP 接続は Bot に機能を提供します。その機能が持つアクセスは、接続されたアカウントと環境によって決まります。[接続](/ja/bot/concepts/brain-and-computers)を参照してください。

<a id="review-and-remove-access"></a>

## アクセスを見直して削除する

定期的に、また Bot の役割が変わったときに権限を確認します。アクセスが不要になったら、接続アプリで権限を取り消し、必要に応じて該当する MCP サーバーを切断します。サーバーを切断しても、アプリ内のアカウント権限は自動的に取り消されません。インシデントが疑われる場合は組織の対応手順に従い、アクセスを確認する間 Bot を停止することを検討します。

現在 Klex は個々の操作の承認や制限をサポートしていません。権限の境界を守るためにプロンプトだけに頼らず、接続アプリのアクセス制御を使ってください。[Klex Bot を制御する](/ja/bot/guides/control-and-limits)を参照してください。
