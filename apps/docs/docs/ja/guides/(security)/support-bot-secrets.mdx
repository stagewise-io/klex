顧客対応 Bot には、サポート依頼への回答に必要な情報と操作だけへのアクセスを付与してください。秘密を守るよう Bot に指示するだけで漏えいを防げるとは限りません。

<a id="reduce-what-the-bot-can-access"></a>

## Bot のアクセスを減らす

- Bot に不要な本番環境の認証情報、機密性の高い顧客記録、社内文書へのアクセスを与えないようにします。
- 接続先サービスが許す場合、サポート業務には権限を限定した専用アカウントを使います。データの読み取り、共有、変更の権限を確認します。
- サポートの会話や例に認証情報を含めないでください。連携には組織で承認された認証情報の管理手順を使います。
- 接続先サービスごとに、Bot に連絡できる人と回答を見られる人を確認します。

<a id="review-the-workflow"></a>

## ワークフローを確認する

機密性のないデータを使い、想定範囲外の情報を得ようとする依頼も含めてテストします。結果と接続先サービスの権限を確認してください。Bot が悪意ある依頼を必ず拒否するとは限りません。

認証情報や機密情報が漏えいした可能性がある場合は、インシデント対応手順に従います。影響を受けた認証情報を失効または更新し、関連するアクセスとアクティビティを確認します。[情報の窃取を防ぐ](/ja/guides/prevent-information-theft)と[影響範囲を制限する](/ja/guides/limit-blast-radius)を参照してください。
