Bot が常に正しく判断し、指示に完全に従うとは限りません。機密性の高い作業や影響の大きい作業では、誤った操作の結果を評価し、独立した安全対策を設けてください。

<a id="start-with-lower-risk-work"></a>

## リスクの低い作業から始める

- 変更を適用する権限を与える前に、Bot に情報収集や変更案の準備を任せます。
- 本番以外のリソースでテストし、結果を確認します。ワークフローと障害への対処を理解してからアクセスを拡大してください。
- 接続アプリごとに Bot アカウントの権限を制限します。不要な破壊的操作や機密性の高い操作の権限は与えません。

<a id="keep-an-independent-check"></a>

## 独立した確認を維持する

人の承認が必要な操作では、変更を適用する前に Bot の外で承認を行います。例えば、Bot が変更を準備し、人が別のアカウントで確認して適用できます。現在 Klex は個々の操作の承認や制限をサポートしていません。先に尋ねるよう指示しても、強制される承認管理にはなりません。

接続先サービスの管理機能と組織の手順を使って、活動の確認、問題の検出、誤りからの復旧を行います。必要に応じて Bot を停止し、アクセスを取り消す方法をあらかじめ決めてください。[Klex Bot を制御する](/ja/bot/guides/control-and-limits)と[影響範囲を制限する](/ja/guides/limit-blast-radius)を参照してください。
