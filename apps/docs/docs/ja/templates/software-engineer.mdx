Software Engineer テンプレートは、チケットからマージ済みのプルリクエストまで開発作業を担当する Klex Bot を設定します。Bot は接続したコンピューターで Claude Code や Codex CLI などのコーディングエージェントの CLI を実行し、その成果をすべて確認します。プルリクエスト、CI、チケット、チームへの報告も自分で担当します。変更が数行で、指示を書くより速い場合に限り、手作業でコードを書きます。

<Panel title="知っておくと便利">
Bot テンプレートは [Klex Cloud](https://cloud.klex.bot) で管理します。Klex Cloud を使わず Klex をセルフホストしている場合も、MCP でコンピューターを接続し、同等の Agent Skills を Bot のデータディレクトリに追加すれば同じ手順を利用できます。
</Panel>

## 日々の作業の流れ

Software Engineer Bot は、人間のエンジニアがコーディングエージェントを指揮するときと同じ流れで作業します。

1. **チケットを読み、範囲を明確にする。** Bot は Linear、Jira、GitHub Issues のチケットと関連コード、最近の Git 履歴を読みます。目的や受け入れ基準が不明な場合は、開始前に依頼者に確認します。
2. **各タスクを worktree とターミナルセッションに分離する。** タスクごとに Git worktree とブランチを作成し、たとえば `git worktree add ../repo-task-a -b task-a origin/main` を使います。名前付き `tmux` セッションでエージェントを起動し、引き渡す前に依存関係をインストールしてテストの実行を確認します。通常は 1 エージェントですが、独立した複数のタスクでは 2〜4 エージェントを並列に動かし、それぞれのブランチを追跡できます。
3. **具体的な指示を書き、監督する。** 各エージェントに目的、確認するファイルやチケット、制約、テスト・lint・型チェックの正確なコマンドを渡します。Bot は実行中のセッションを確認し、停滞したら追加指示を送り、ループしたら停止して指示を書き直します。
4. **PR を開く前に成果を確認する。** エージェントが未確認の作業を成功と報告する場合があるため、Bot は `git diff origin/main...HEAD` の全体を読みます。テスト、lint、型チェックを自分で実行し、ユーザー向けの動作と、弱められたテスト、架空の API、握りつぶされたエラー、重複ヘルパー、残った一時ファイルを確認します。問題があればファイルと行を示した番号付き修正を送り、2 回進展がなければ自分で直します。統合後は `git worktree remove` で未使用の worktree を削除します。
5. **CI とレビューを通してプルリクエストを担当する。** リポジトリのブランチ、コミット、PR の規約に従った絞り込んだ PR を、チケットを読んでいないレビュアー向けに説明します。各 push 後に CI と失敗ログを確認し、問題をローカルで再現して原因を修正します。人間とレビューボットの全コメントに回答し、必要なチェックと承認が済み、マージ権限がある場合だけマージします。デプロイを確認し、チケットを更新してチャットで状況を報告します。
6. **チームのプルリクエストをレビューする。** 依頼されたら関連チケットと差分全体を読み、正確性、安全性、設計、テスト、読みやすさの順に確認します。必須の問題と任意の指摘を分け、確認済みの所見だけを投稿します。

## テンプレートの内容

[Klex Cloud](https://cloud.klex.bot) の Software Engineer テンプレートは、Bot の soul、デフォルト設定、管理対象 skills、ツールカテゴリ、初回オンボーディングのチェックリストを設定します。

### Skills

Klex Cloud は Bot が接続するたびに、これらの skills を Bot の `templates` 名前空間に同期しようとします。template skills に対応した Bot バージョンが必要で、同期が失敗することもあります。

| Skill | 内容 |
| --- | --- |
| `set-up-coding-agents` | チームが契約しているコーディングエージェント CLI を選び、公式ドキュメントに従って接続済みまたは管理対象のコンピューターにインストールし、チャットで秘密情報を求めずブラウザーでのサインインを案内します。 |
| `delegate-to-coding-agents` | チケットを計画し、分離した Git worktree と名前付き `tmux` セッションを準備し、エージェントへの指示、並列実行の監督、完了した worktree の削除を行います。 |
| `review-agent-work` | 差分全体を読み、自分でチェックを実行し、よくある誤りを見つけ、具体的な修正を送り、PR 前にコミットを整理します。 |
| `own-pull-requests` | 対象を絞った PR を開き、CI を正常に保ち、レビューに回答してマージとデプロイまで追跡します。 |
| `review-pull-requests` | チームの PR を正確性、安全性、設計、テスト、読みやすさで確認し、必須の修正と任意の提案を分けます。 |
| `connect-your-tools` | テンプレートのツールカテゴリを示し、Bot が役立つツールを把握して Klex Cloud コネクタまたはカスタム MCP サーバー経由の接続を提案できるようにします。 |

### ツールカテゴリ

チームがすでに使っているツールを、Klex Cloud コネクタまたはカスタム MCP サーバー経由で接続できます。

- **ソース管理。** GitHub, GitLab, Bitbucket.
- **課題管理。** Linear, Jira, GitHub Issues.
- **CI。** GitHub Actions, Vercel, CircleCI, Buildkite.
- **ドキュメントと知識。** Notion, Confluence, Google Docs.
- **チャット。** Slack, Teams, Discord.
- **その他のツール。** Sentry、PostHog、Figma、クラウドコンソール、MCP 経由のデータベース。

### デフォルトとオンボーディング

デフォルトでは高性能なモデルの階層を使い、独自のコンピューターを接続しない場合は中規模のクラウドコンピューターを推奨し、`test-first` と `small-prs` の特性を有効にします。`nitpicker` と `boy-scout` も有効にできます。

Cloud は Bot の接続時に次の初期タスクを追加しようとします。Bot が todos API に対応している必要があります。

1. 利用するリポジトリ、課題管理、CI を特定し、それぞれのアクセスを確認する。
2. チームが使う Claude Code、Codex、Cursor などを確認し、アクセス可能なコンピューターを接続する。
3. Cloud チャット、Slack、Teams など、主な連絡先を決める。
4. ブランチ名、必要なレビューとチェック、マージ担当者など、チームの PR 規約を学ぶ。
5. 最初の課題またはタスクを選ぶ。

## ベストプラクティス

- **Bot 専用のアカウントを用意する。** GitHub、Linear、Slack の専用 ID を作り、権限を限定してコミット、コメント、状態変更を追跡できるようにします。[別々の ID を作成する](/ja/guides/bot-identities)を参照してください。
- **開発の背景を共有する。** 会社のハンドブック、アーキテクチャ文書、リポジトリの貢献ガイドへのアクセスを Bot に付与します。[会社のハンドブックを作成する](/ja/guides/company-handbook)を参照してください。
- **Bot 間の引き継ぎに共有チャンネルを使う。** Product Manager Bot がチケットを作り、Software Engineer Bot が実装する場合は、`#bot-communication` のように人間も読めるチャンネルに配置します。[共有メッセージボードを使う](/ja/guides/shared-messaging-boards)を参照してください。
- **コーディング CLI では API キーよりサブスクリプションを優先する。** API キーでトークンごとに課金する代わりに、ブラウザーからチームのサブスクリプションにサインインします。秘密情報をチャット、チケット、リポジトリに置かないでください。API キーしか対応しないプロバイダーでは、コンピューターに直接キーを設定します。
- **マージ規則を早めに決める。** チェックと承認後に Bot が自分の PR をマージできるか、常に人間がマージするかを決めます。テストコマンドと PR レビューの流れがチームの期待に合うまで、小さく範囲の明確なチケットから始めます。
