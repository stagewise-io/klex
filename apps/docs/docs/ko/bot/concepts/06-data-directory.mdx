각 Klex 봇은 대화와 메모리를 자체 데이터 디렉터리에 저장합니다. 클라우드 호스팅 봇의 디렉터리는 호스팅 환경에 있습니다. 셀프 호스팅 봇의 디렉터리는 봇의 데이터를 저장하는 로컬 폴더에 있습니다.

관리자는 봇의 Admin API를 통해 대화와 Skills를 확인할 수 있습니다. Klex Cloud 대시보드는 각 봇의 Admin API에 대한 리버스 프록시와 프런트엔드 역할을 합니다.

## 봇 데이터 찾기 및 보호하기

<Tabs syncKey="hosting" hash={false}>
<Tab title="클라우드 호스팅">

봇의 활동을 확인하려면 Klex Cloud에서 해당 봇을 여세요. 데이터 디렉터리는 호스팅 환경에 있습니다. 클라우드 호스팅 데이터의 보호 방법은 [데이터 개인정보 보호](/cloud/data-privacy)를 참고하세요.

</Tab>
<Tab title="셀프 호스팅">

<a id="find-a-self-hosted-bot"></a>
<a id="셀프-호스팅-봇-찾기"></a>

셀프 호스팅 Klex 앱을 대화형으로 시작하면 기본적으로 `~/.klex/agents`에서 봇을 찾습니다. `KLEX_HOME`이 설정되어 있으면 해당 경로의 `agents` 폴더를 사용합니다. `--data-dir`로 디렉터리를 직접 지정할 수 있으며 이 옵션은 `KLEX_DATA_DIR`보다 우선합니다.

예를 들어 데이터 디렉터리를 알고 있는 봇을 열려면 다음을 실행합니다.

```sh
klex --data-dir /path/to/bot
```

예시 경로를 실제 봇 디렉터리로 바꾸세요. Cloud 없이 봇을 만들거나 헤드리스로 실행하는 방법은 [독립 실행 설정 가이드](/bot/guides/standalone-setup)를 참고하세요.

<a id="protect-the-data"></a>
<a id="데이터-보호"></a>

### 로컬 디렉터리 보호하기

디렉터리에는 설정과 인증 정보 같은 민감한 정보가 포함될 수 있습니다. 운영체제 권한으로 접근을 제한하고 생성한 사본도 보호하세요. Unix 파일 모드를 사용하는 시스템에서 Klex는 디렉터리 생성 시 소유자만 접근할 수 있는 권한을 요청합니다. 기존 디렉터리의 권한은 변경하지 않습니다. Windows는 액세스 제어 목록을 사용합니다.

데이터를 삭제하거나 이동하기 전에 백업 및 복구 절차를 확인하세요.
