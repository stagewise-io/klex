[Model Context Protocol(MCP)](https://modelcontextprotocol.io/)은 Klex Bot을 외부 환경에 연결합니다. MCP 서버는 컴퓨터나 앱을 제공할 수 있으며, Bot은 서버가 제공하는 기능을 사용해 그곳에서 작업합니다.

Klex는 내장 MCP 서버를 제공하며 다른 MCP 서버도 지원합니다. 사용할 수 있는 기능은 서버에 따라 다릅니다.

- **도구**를 사용하면 Bot이 서버에 작업이나 정보를 요청할 수 있습니다.
- **리소스**는 Bot이 찾아서 열 수 있는 콘텐츠를 제공합니다.
- 서버가 [Klex MCP Push Notifications 확장](https://github.com/stagewise-io/klex/tree/main/packages/mcp-extension-push-notifications)을 지원하면 **푸시 알림**으로 메시지와 그 밖의 이벤트를 전달할 수 있습니다.
- MCP 확장 초안인 **MCP Events & Triggers**를 사용하면 Bot이 지원되는 서버 이벤트를 찾아 감시할 수 있습니다. 감시는 채팅과 재시작을 넘어 유지되지만, 서비스 중단 중에 발생한 이벤트는 유실될 수 있습니다. 감시를 설정해도 외부 서비스가 자동으로 설정되지는 않습니다.

이러한 MCP 기능은 메시지가 도착하거나 앱에서 변화가 생길 때 Bot이 작업하도록 할 수 있습니다. 연결된 서버의 지원과 설정에 따라 사용할 수 있으며, 별도의 Klex 전용 게이트웨이는 필요하지 않습니다.

<a id="adding-a-server"></a>

## 서버 추가

Cloud 대시보드에서 Bot의 MCP 연결을 관리할 수 있습니다. Bot도 새 원격 HTTP 또는 HTTPS MCP 서버를 직접 추가할 수 있습니다. 이 서버 추가 기능으로는 기존 서버 설정을 수정하거나 삭제할 수 없습니다. 새 서버에 OAuth가 필요하면 사용자가 Cloud 화면에서 인증할 수 있습니다.

신뢰할 수 있는 서버만 연결하세요. 서버를 연결하면 Bot이 해당 서버의 기능을 사용할 수 있지만, 앱 내부의 접근 권한은 그 앱에 설정된 계정과 권한에도 따라 달라집니다. Bot의 연결을 검토하고 계정에는 필요한 접근 권한만 부여하세요. 접근 관리에 관한 자세한 내용은 [컴퓨터와 앱 연결](/ko/bot/concepts/brain-and-computers)을 참조하세요.

Bot은 MCP를 통해 앱에 연결합니다. Bot의 계정은 앱 안에 있으며 연결과 별도로 관리됩니다.

<a id="add-a-remote-server"></a>

### 원격 서버 추가

<Tabs syncKey="hosting" hash={false}>
<Tab title="Cloud 호스팅">

1. Klex Cloud에서 Bot을 열고 **Connectors**를 선택합니다. 커넥터를 관리하려면 조직 소유자 또는 관리자 권한이 필요합니다.
2. 커넥터 카탈로그에서 **Connect an MCP**를 선택하고 서버 URL과 이름을 입력합니다. 필요한 헤더는 **Advanced options**에서 추가합니다.
3. **Connect**를 선택하고 메시지가 표시되면 인증을 완료합니다. 서버를 사용하기 전에 연결 상태를 확인하세요.

</Tab>
<Tab title="셀프 호스팅">

<a id="add-a-remote-server-in-the-self-hosted-app"></a>

대화형 Klex 앱에서 스트리밍 가능한 HTTP 서버를 추가할 수 있습니다.

1. **Settings → MCP Servers**를 열고 `a`를 누릅니다.
2. 고유한 서버 이름과 절대 HTTP 또는 HTTPS URL을 입력합니다. 자격 증명을 전송하는 원격 서비스에는 HTTPS를 사용하세요.
3. 서버에 사용자 지정 헤더가 필요하면 `a`를 눌러 각 이름과 값을 추가합니다. 자격 증명 값은 비밀로 취급하세요.
4. `s`를 눌러 서버를 추가한 다음 서버 목록에서 상태를 확인합니다. 설정을 저장했다고 해서 서버가 연결된 것은 아닙니다.

서버를 확인하려면 서버를 선택하고 Enter를 누릅니다. 상세 화면에는 상태, 전송 방식, 도구 수와 푸시 알림 지원 여부가 표시됩니다. 여기서 `e`로 설정을 수정하고 `d`로 확인 후 서버를 삭제할 수 있습니다. 삭제 시 Klex는 로컬 OAuth 자격 증명을 지우고, 공급자가 지원하면 토큰 폐기를 시도합니다. 폐기가 실패할 수 있으므로 연결된 앱에서 계정 권한을 별도로 확인하세요.

</Tab>
</Tabs>

Cloud 화면을 통해 OAuth 인증을 하려면 Bot이 Cloud에 등록되어 있고 Cloud 터널이 연결되어 있어야 합니다. Cloud에 등록되지 않은 독립 실행형 Bot은 이 Cloud 중계 인증 절차를 사용할 수 없습니다.

<a id="if-a-connection-needs-attention"></a>

## 연결에 문제가 있을 때

서버에 인증이 필요하거나 연결에 실패할 수 있습니다. 연결 상태를 확인하고 필요한 인증을 완료하세요. 여전히 연결할 수 없다면 서버 주소와 자격 증명, 서버의 가용성을 확인하세요. Bot은 연결된 서버가 제공하는 기능만 사용할 수 있습니다.
