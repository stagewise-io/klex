Bot의 채팅과 메모리는 [데이터 디렉터리](/ko/bot/concepts/data-directory)에 저장됩니다. Cloud 호스팅 Bot의 디렉터리는 호스팅 환경에 있습니다. 자체 호스팅 Bot의 디렉터리는 Bot을 실행하는 환경에 있습니다. 관리자는 Bot의 Admin API를 통해 채팅과 스킬을 검토할 수 있습니다.

Cloud 호스팅 Bot의 모든 데이터는 메모리를 포함해 전송 중과 저장 시 암호화됩니다. 이 설명은 자체 호스팅 Bot의 암호화에 관한 것이 아닙니다. 자체 호스팅 환경과 저장소를 적절하게 보호하세요.

<a id="access-and-connected-services"></a>

## 접근과 연결된 서비스

Bot은 계정의 권한을 사용해 연결된 앱에서 작업할 수 있습니다. 민감한 정보를 사용하기 전에 각 계정이 접근할 수 있는 데이터와 작업, 연결된 서비스 및 모델 제공업체의 정책을 검토하세요. [Klex Bot 안전하게 사용하기](/ko/guides/secure-bot-usage)를 참고하세요.

Cloud 호스팅 Bot을 디버깅할 때 Klex의 제한된 직원이 조사에 관해 사용자와 논의하고 확인을 받은 후 디버그 모드에서 Bot의 채팅이나 메모리에 접근할 수 있습니다. 이 접근은 영구적으로 기록되고 사용자에게 표시되며 일반적으로 시간 제한이 있습니다. 일반적인 모델 훈련에는 사용되지 않습니다.

[개인정보 처리방침](https://klex.bot/legal/privacy)과 [데이터 처리 계약](https://klex.bot/legal/data-processing-agreement)은 지원 디버깅, 기타 처리, 서비스 제공업체 및 보존에 관해 설명합니다. 보안 또는 법적 사유에 따른 별도의 적법한 처리도 다룹니다. 사용 사례에 적용되는 약관과 연결된 제공업체의 정책을 확인하세요.

## 분석과 텔레메트리

<Tabs syncKey="hosting" hash={false}>
<Tab title="Cloud 호스팅">

Cloud 측 처리, 서비스 제공업체 및 보존에 관해서는 [개인정보 처리방침](https://klex.bot/legal/privacy)과 [데이터 처리 계약](https://klex.bot/legal/data-processing-agreement)을 참고하세요. 자체 호스팅 프로세스 플래그는 Cloud 측 보고를 설명하지 않습니다.

</Tab>
<Tab title="자체 호스팅">

<a id="analytics-and-telemetry-for-a-self-hosted-bot"></a>

Klex에는 별도의 보고 시스템 두 개가 있습니다. 아래 제어는 자체 호스팅 Klex 프로세스에 적용되며 Cloud 측 보고나 연결된 서비스를 설명하지 않습니다.

**제품 분석**은 분석 키가 포함된 릴리스 빌드에서 기본적으로 활성화됩니다. 이벤트에는 시작과 등록 결과, 집계된 사용량, 런타임 정보 및 프로세스 리소스 사용량이 포함될 수 있습니다. 이벤트 스키마에는 채팅 내용이나 등록 토큰이 포함되지 않습니다. 각 프로세스는 임시 무작위 식별자를 사용하며 네트워크 요청은 수신자에게 발신자의 IP 주소를 노출합니다. [제품 분석 구현 세부 정보](https://github.com/stagewise-io/klex/blob/baff8a40ce9b896fdd17146dfe9906cefe7c2697/apps/klex/product-analytics.md)를 참고하세요.

제품 분석을 끄려면 Klex를 `--no-analytics`와 함께 시작하거나 환경에서 `KLEX_NO_ANALYTICS=1` 또는 `DO_NOT_TRACK=1`을 설정하세요. 명시적 `--analytics` 플래그는 환경 변수를 통한 거부보다 우선합니다.

**운영 텔레메트리**는 별도입니다. 텔레메트리 엔드포인트가 설정되지 않으면 꺼져 있습니다. 명시적으로 비활성화하지 않은 경우 엔드포인트를 설정하면 활성화됩니다. 활성화 시 기본 수준에는 민감한 운영 메타데이터가 포함됩니다. 디버그 수준은 채팅 내용, 프롬프트 및 도구 페이로드도 내보낼 수 있습니다. 신뢰할 수 있는 수집기만 사용하고 해당 데이터에 대한 접근을 제한하세요. 텔레메트리를 강제로 끄려면 `--disable-telemetry` 또는 `KLEX_DISABLE_TELEMETRY=1`을 사용하세요. [텔레메트리 구현 세부 정보](https://github.com/stagewise-io/klex/blob/baff8a40ce9b896fdd17146dfe9906cefe7c2697/apps/klex/telemetry.md)를 참고하세요.

한 시스템을 꺼도 다른 시스템은 꺼지지 않습니다. 어느 제어도 구성된 모델 제공업체, MCP 서버 또는 Cloud 연결과의 통신을 끄지 않습니다.
