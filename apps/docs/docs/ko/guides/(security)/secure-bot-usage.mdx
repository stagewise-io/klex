대부분의 연결된 앱에서 Bot은 자신의 계정으로 작동합니다. 앱에서 해당 계정의 권한을 설정하세요. Bot에 맡은 업무에 필요한 접근 권한만 부여하고 업무가 바뀌면 검토하세요.

<a id="before-connecting-an-app"></a>

## 앱을 연결하기 전에

1. Bot에 필요한 리소스와 작업을 파악하세요. 읽기 전용 접근으로 충분하면 그 권한부터 시작하세요.
2. 앱이 해당 범위를 지원하면 Bot 계정에 조직 전체가 아닌 관련 프로젝트, 폴더 또는 대화에 대한 접근 권한을 부여하세요.
3. 계정이 데이터를 공유하거나 설정을 변경하고 리소스를 삭제하거나 다른 민감한 작업을 수행할 수 있는지 확인하세요. 불필요한 권한은 제거하세요.
4. 의도한 워크플로를 민감하지 않은 데이터로 시험하고 결과를 검토하세요.

연결된 컴퓨터를 포함한 각 연결에 이 검토를 반복하세요. MCP 연결은 Bot에 기능을 제공하며, 연결된 계정과 환경이 그 기능의 접근 범위를 결정합니다. [연결](/ko/bot/concepts/brain-and-computers)을 참고하세요.

<a id="review-and-remove-access"></a>

## 접근 권한 검토 및 제거

권한을 정기적으로, 그리고 Bot의 역할이 바뀔 때 검토하세요. 접근이 더 이상 필요하지 않으면 연결된 앱에서 권한을 취소하고 적절한 경우 해당 MCP 서버 연결을 해제하세요. 서버 연결 해제만으로는 앱의 계정 권한이 취소되지 않습니다. 사고가 의심되면 조직의 사고 대응 절차를 따르고 접근을 검토하는 동안 Bot 중지를 고려하세요.

현재 Klex는 개별 작업의 승인이나 제한을 지원하지 않습니다. 권한 경계를 강제하기 위해 프롬프트에만 의존하지 말고 연결된 앱의 접근 제어를 사용하세요. [Klex Bot 제어하기](/ko/bot/guides/control-and-limits)를 참고하세요.
