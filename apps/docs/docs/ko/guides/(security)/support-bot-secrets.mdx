고객을 상대하는 Bot에는 지원 요청에 답하는 데 필요한 정보와 작업에만 접근 권한을 부여해야 합니다. Bot에 비밀을 지키라고 지시하는 것만으로 공개를 막을 수 있다고 가정하지 마세요.

<a id="reduce-what-the-bot-can-access"></a>

## Bot의 접근 범위 줄이기

- Bot에 필요하지 않은 프로덕션 자격 증명, 민감한 고객 기록 또는 내부 문서에 대한 접근 권한을 주지 마세요.
- 연결된 서비스가 허용한다면 지원 업무에 범위가 좁은 별도 계정을 사용하세요. 데이터 읽기, 공유 및 변경 권한을 검토하세요.
- 지원 대화와 예시에 자격 증명을 넣지 마세요. 통합에는 조직에서 승인한 자격 증명 관리 절차를 사용하세요.
- 각 연결 서비스에서 누가 Bot에 연락하고 응답을 볼 수 있는지 확인하세요.

<a id="review-the-workflow"></a>

## 워크플로 검토

민감하지 않은 데이터로 시험하고 예상 범위 밖의 정보를 얻으려는 요청도 포함하세요. 결과와 연결된 서비스의 권한을 검토하세요. Bot이 악의적인 요청을 항상 거부한다고 가정하지 마세요.

자격 증명이나 민감한 정보가 노출되었을 가능성이 있다면 사고 대응 절차를 따르세요. 영향을 받은 자격 증명을 취소하거나 교체하고 관련 접근과 활동을 검토하세요. [정보 도난 방지](/ko/guides/prevent-information-theft)와 [영향 범위 제한](/ko/guides/limit-blast-radius)을 참고하세요.
