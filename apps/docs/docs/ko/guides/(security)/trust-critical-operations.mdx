Bot이 항상 올바른 결정을 내리거나 지시를 완벽하게 따른다고 가정하지 마세요. 민감하거나 영향이 큰 작업은 잘못된 행동의 결과를 평가하고 독립적인 안전장치를 마련하세요.

<a id="start-with-lower-risk-work"></a>

## 위험이 낮은 작업부터 시작하기

- 변경을 적용할 접근 권한을 주기 전에 Bot이 정보를 수집하거나 변경안을 준비하도록 하세요.
- 프로덕션이 아닌 리소스로 시험하고 결과를 검토하세요. 워크플로와 실패 처리 방식을 이해한 뒤에만 접근 권한을 확대하세요.
- 각 연결 앱에서 Bot 계정의 권한을 제한하세요. 필요하지 않은 파괴적이거나 민감한 권한은 부여하지 마세요.

<a id="keep-an-independent-check"></a>

## 독립적인 확인 유지하기

사람의 승인이 필요한 작업은 변경을 적용하기 전에 Bot 외부에서 승인을 받도록 하세요. 예를 들어 Bot이 변경을 준비하면 사람이 별도 계정으로 검토하고 적용할 수 있습니다. 현재 Klex는 개별 작업의 승인이나 제한을 지원하지 않습니다. 먼저 물어보라는 지시는 강제되는 승인 통제가 아닙니다.

연결된 서비스의 통제 기능과 조직의 절차를 사용해 활동을 검토하고 문제를 감지하며 실수를 복구하세요. 필요할 때 Bot을 중지하고 접근 권한을 취소하는 방법을 미리 정하세요. [Klex Bot 제어하기](/ko/bot/guides/control-and-limits)와 [영향 범위 제한](/ko/guides/limit-blast-radius)을 참고하세요.
