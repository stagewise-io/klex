Каждый бот Klex хранит разговоры и память в своём каталоге данных. У бота, размещённого в Cloud, каталог находится в облачной среде. У самостоятельно размещённого бота он находится в локальной папке, используемой для его данных.

Администраторы могут просматривать разговоры и навыки через Admin API бота. Панель Klex Cloud служит обратным прокси и интерфейсом для Admin API каждого бота.

## Как найти и защитить данные бота

<Tabs syncKey="hosting" hash={false}>
<Tab title="Размещённый в Cloud">

Откройте бота в Klex Cloud, чтобы просмотреть его активность. Каталог данных находится в облачной среде. Подробнее о защите данных ботов в Cloud см. в разделе [Конфиденциальность данных](/cloud/data-privacy).

</Tab>
<Tab title="Самостоятельно размещённый">

<a id="find-a-self-hosted-bot"></a>
<a id="поиск-самостоятельно-размещённого-бота"></a>

В самостоятельно размещённом приложении Klex интерактивный запуск по умолчанию ищет ботов в `~/.klex/agents`. Если задан `KLEX_HOME`, используется папка `agents` по этому пути. С помощью `--data-dir` можно выбрать каталог напрямую; этот параметр имеет приоритет над `KLEX_DATA_DIR`.

Например, чтобы открыть бота, каталог данных которого вам уже известен:

```sh
klex --data-dir /path/to/bot
```

Замените пример пути реальным каталогом бота. Чтобы создать бота без Cloud или запустить его без терминального интерфейса, см. [руководство по автономной установке](/bot/guides/standalone-setup).

<a id="protect-the-data"></a>
<a id="защита-данных"></a>

### Защита локального каталога

Каталог может содержать конфиденциальные сведения, в том числе конфигурацию и учётные данные. Ограничьте доступ с помощью разрешений операционной системы и защитите создаваемые копии. В системах с файловыми режимами Unix Klex запрашивает права только для владельца при создании каталога; права существующих каталогов он не меняет. Windows использует списки управления доступом.

Перед удалением или перемещением данных проверьте свои процедуры резервного копирования и восстановления.
