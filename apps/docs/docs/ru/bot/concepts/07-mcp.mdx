[Model Context Protocol (MCP)](https://modelcontextprotocol.io/) соединяет Klex Bot с внешними средами. Сервер MCP может предоставлять доступ к компьютеру или приложению; Bot использует возможности сервера для работы с ними.

Klex предлагает встроенные серверы MCP и поддерживает другие серверы MCP. Доступные возможности зависят от сервера:

- **Инструменты** позволяют Bot запрашивать у сервера действия или информацию.
- **Ресурсы** предоставляют содержимое, которое Bot может находить и открывать.
- **Push-уведомления** могут доставлять сообщения и другие события, если сервер поддерживает [расширение Klex MCP Push Notifications](https://github.com/stagewise-io/klex/tree/main/packages/mcp-extension-push-notifications).
- **MCP Events & Triggers**, проект расширения MCP, позволяет Bot находить и отслеживать поддерживаемые события сервера. Подписки сохраняются между чатами и перезапусками, но события во время простоя могут быть потеряны. Создание подписки не настраивает внешний сервис.

Эти возможности MCP могут побудить Bot к работе при получении сообщения или изменении в приложении. Они зависят от поддержки и настройки подключённого сервера; отдельный шлюз для Klex не нужен.

<a id="adding-a-server"></a>

## Добавление сервера

Управлять MCP-подключениями Bot можно в панели Cloud. Bot также может сам добавить новый удалённый сервер MCP по HTTP или HTTPS. Эта функция не позволяет изменять или удалять существующие конфигурации серверов. Если новому серверу нужен OAuth, пользователь может авторизовать его в интерфейсе Cloud.

Подключайте только доверенные серверы. Подключение предоставляет Bot доступ к возможностям сервера; доступ внутри приложения также зависит от настроенной там учётной записи и её разрешений. Проверяйте подключения Bot и предоставляйте его учётным записям только необходимый доступ. Подробнее об управлении доступом см. [Подключения к компьютерам и приложениям](/bot/concepts/brain-and-computers).

Bot соединяется с приложением через MCP. Его учётная запись находится в приложении и существует отдельно от подключения.

<a id="add-a-remote-server"></a>

### Добавление удалённого сервера

<Tabs syncKey="hosting" hash={false}>
<Tab title="В облаке">

1. В Klex Cloud откройте свой Bot и выберите **Connectors**. Для управления коннекторами нужны права владельца или администратора организации.
2. В каталоге коннекторов выберите **Connect an MCP**, введите URL и имя сервера и добавьте необходимые заголовки в **Advanced options**.
3. Выберите **Connect** и завершите авторизацию, если появится запрос. Проверьте статус подключения, прежде чем использовать сервер.

</Tab>
<Tab title="На своём хостинге">

<a id="add-a-remote-server-in-the-self-hosted-app"></a>

В интерактивном приложении Klex можно добавить сервер streamable HTTP:

1. Откройте **Settings → MCP Servers** и нажмите `a`.
2. Введите уникальное имя сервера и абсолютный URL HTTP или HTTPS. Для удалённых сервисов, передающих учётные данные, используйте HTTPS.
3. Если серверу нужны дополнительные заголовки, нажмите `a`, чтобы добавить каждое имя и значение. Храните значения учётных данных в секрете.
4. Нажмите `s`, чтобы добавить сервер, и проверьте его статус в списке. Сохранённая конфигурация сама по себе не означает, что сервер подключён.

Чтобы просмотреть сервер, выберите его и нажмите Enter. На экране сведений показаны статус, транспорт, количество инструментов и поддержка push-уведомлений. Там `e` изменяет конфигурацию, а `d` удаляет сервер после подтверждения. При удалении Klex удаляет локальные учётные данные OAuth и пытается отозвать токен, если провайдер это поддерживает. Отзыв может не выполниться, поэтому отдельно проверьте разрешения учётной записи в подключённом приложении.

</Tab>
</Tabs>

Для авторизации через OAuth в интерфейсе Cloud Bot должен быть зарегистрирован в Cloud и иметь подключённый туннель Cloud. Отдельный Bot без регистрации в Cloud не может использовать эту авторизацию через Cloud.

<a id="if-a-connection-needs-attention"></a>

## Если подключение требует внимания

Серверу может понадобиться авторизация, или подключение может завершиться ошибкой. Проверьте статус подключения и выполните необходимую авторизацию. Если подключиться по-прежнему не удаётся, проверьте адрес сервера, учётные данные и доступность сервера. Bot может использовать только возможности, предоставляемые подключённым сервером.
