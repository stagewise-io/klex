На [панели Klex Cloud](https://cloud.klex.bot) можно видеть, чем занимается бот, и общаться с ним.

Администраторы также могут просматривать чаты и навыки бота через его Admin API. Панель Cloud предоставляет интерфейс к Admin API каждого бота. О месте хранения данных см. [каталог данных](/ru/bot/concepts/data-directory).

<a id="review-activity-and-diagnostics"></a>

## Просмотр активности и диагностики

<Tabs syncKey="hosting" hash={false}>
<Tab title="Размещённый в Cloud">

В Klex Cloud откройте бота и выберите **Activity**, чтобы просмотреть его недавнюю работу. Выберите действие для просмотра подробностей и используйте **Load older activity**, чтобы увидеть более ранние действия, если они доступны. Представление активности может не содержать все предыдущие события.

</Tab>
<Tab title="Самостоятельный хостинг">

<a id="check-self-hosted-diagnostics"></a>

В интерактивном приложении Klex откройте **Settings → Logs**, чтобы просмотреть недавние журналы выполнения. Используйте стрелки для прокрутки, `l` для изменения минимального отображаемого уровня и `v` для изменения стиля отображения. Изменение отображаемого уровня не обязательно включает сбор дополнительных журналов.

Просмотрщик хранит в памяти до 500 захваченных записей текущего процесса, поэтому более старые записи могут быть недоступны. Журналы выполнения не являются полной записью разговоров бота или результатов задач. В режиме headless Klex пишет журналы в консоль вместо интерактивного просмотрщика.

Для сведений о версии и подключении откройте **Settings → Debug Information**. Здесь показаны версия Klex, каталог данных и, при наличии, состояние регистрации в Cloud и туннеля. Перед публикацией проверьте журналы и диагностику на наличие конфиденциальной информации.

</Tab>
</Tabs>

<a id="if-a-bot-does-not-respond"></a>

## Если бот не отвечает

Проверьте каждую часть пути, начиная с бота и заканчивая источником сообщения:

1. **Проверьте, что бот работает.** Для бота на самостоятельном хостинге проверьте его процесс или службу. Если включён необязательный listener состояния, проверьте его endpoint готовности. Успешная проверка не доказывает, что модель или подключения работают.
2. **Проверьте доступ к модели.** Убедитесь, что провайдер настроен и модель чата выбрана. При ошибках запросов проверьте учётную запись и сервис провайдера. См. [Модели](/ru/bot/concepts/models).
3. **Проверьте подключение и учётную запись.** Для сообщения из подключённого приложения проверьте состояние MCP-сервера, необходимую авторизацию и доступ учётной записи бота к разговору. Доставка событий также зависит от возможностей сервера. См. [MCP и боты Klex](/ru/bot/concepts/mcp#if-a-connection-needs-attention).
4. **Просмотрите доступную активность и журналы.** Найдите ошибки примерно во время запроса. Используйте панель Cloud, если она доступна, или описанную выше диагностику самостоятельного хостинга. Журналы и активность могут быть неполными; отсутствие записи само по себе не определяет место сбоя доставки.

Перед публикацией проверьте диагностику на наличие конфиденциальной информации. Не включайте учётные данные в запрос поддержки.

<a id="review-activity-with-the-admin-api"></a>

## Просмотр активности через Admin API

Администраторы, использующие Admin API, могут:

- Получить список сохранённых экземпляров сессий через `GET /v1/sessions`, затем сообщения сессии через `GET /v1/sessions/{instanceId}/messages`. Используйте `nextCursor` для получения более старых страниц. Некоторые старые сообщения могли быть обрезаны; проверьте `trimmedMessageCount`.
- Изучить текущую активность сессий через `GET /v1/introspect/sessions`. Сведения могут включать `childSessions`, например активные сессии поиска или записи памяти либо консультации. Завершённые дочерние сессии опущены, поэтому это не полная история.
- Запросить записанное использование вызовов модели через `GET /v1/usage`. Результаты можно группировать по модели или провайдеру и агрегировать по времени. Итоговые числа токенов могут быть неполными, если провайдер не сообщает использование; проверьте `tokenUsageUnreportedCount`.

Используйте `GET /v1/openapi.json` для просмотра доступных маршрутов и параметров запроса API. Сообщения сессий и вывод инструментов могут содержать конфиденциальную информацию; ограничьте круг лиц, которые могут получать к ним доступ и хранить их.

<a id="access-activity-data"></a>

### Доступ к данным активности

<Tabs syncKey="hosting" hash={false}>
<Tab title="Размещённый в Cloud">

Используйте панель Klex Cloud для просмотра активности бота и общения с ним. Локальный listener ниже предназначен для ботов на самостоятельном хостинге.

</Tab>
<Tab title="Самостоятельный хостинг">

<a id="access-the-local-admin-api"></a>

Приложение на самостоятельном хостинге по умолчанию не открывает локальный порт Admin API. Его необязательный listener привязан к `127.0.0.1` и **не имеет аутентификации**. Любой, кто может к нему подключиться, включая других локальных пользователей и процессы, может получить конфиденциальные данные бота и использовать маршруты управления. Включайте его только там, где этим пользователям и процессам доверяют; не открывайте и не перенаправляйте его в недоверенную сеть.

Например, чтобы запустить существующего бота в режиме headless с включённым локальным listener:

~~~sh
klex --headless --data-dir /path/to/bot --dangerous-local-admin-api-port 2706
~~~

Замените путь и порт своими значениями. На том же компьютере можно просмотреть доступные маршруты:

~~~sh
curl http://127.0.0.1:2706/v1/openapi.json
~~~

Порт также можно задать через `KLEX_DANGEROUS_LOCAL_ADMIN_API_PORT`; параметр командной строки имеет приоритет. По окончании остановите бота и перезапустите его без параметра или переменной окружения, чтобы отключить listener.

</Tab>
</Tabs>

Чтобы остановить бота или изменить его подключённый доступ, см. [Управление ботом Klex](/ru/bot/guides/control-and-limits).
