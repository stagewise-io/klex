Klex Bot может использовать подключённый компьютер для работы с файлами, выполнения команд и, если доступен рабочий стол, работы с графическими приложениями. Bot — это мозг, а компьютер — инструмент, которым он пользуется. Один Bot может использовать несколько компьютеров, а один компьютер можно назначить нескольким Bots.

Выберите управляемый компьютер в Klex Cloud или подключите свой через MCP-сервер `@klex/machine`. Доступные Bot инструменты зависят от компьютера и его конфигурации.

<a id="before-you-connect"></a>

## Перед подключением

Подключение компьютера даёт Bot значительный доступ. `@klex/machine` может читать и изменять файлы и выполнять команды shell с правами пользователя операционной системы, который его запускает. Рабочий каталог не является изолированной средой: абсолютные пути остаются доступными. Рабочий стол может открыть доступ ко всему, что этот пользователь может видеть или использовать.

По возможности используйте отдельную учётную запись без привилегий или изолированный компьютер. Удалите ненужные учётные данные и конфиденциальную информацию и предоставляйте доступ только Bots и людям, которым доверяете. Независимо проверяйте важные действия. См. [Контроль и ограничения](/ru/bot/guides/control-and-limits).

<a id="use-a-managed-computer"></a>

## Использование управляемого компьютера

В разделе **Computers** вашего Bot выберите **Add computer**, затем **Set up a computer**. Выберите **Cloud computer**, размер и настройку доступа к интернету, проверьте цену и нажмите **Create computer**. Проверьте состояние и возможные ошибки подключения в Cloud: назначение само по себе не гарантирует, что компьютер подключён.

Управляемые компьютеры могут предоставлять рабочий стол для графической работы, а также инструменты для файлов и shell. Когда экран доступен, его можно просматривать в Cloud. Администратор может взять управление и затем вернуть его Bot. Пока управляет человек, ввод Bot на рабочем столе заблокирован. Экран и инструменты доступны в зависимости от состояния компьютера и активности поддержки рабочего стола.

<a id="connect-your-own-computer-to-cloud"></a>

## Подключение своего компьютера к Cloud

На компьютере требуется Node.js 24 или новее. Администратор организации может настроить компьютер в Cloud и назначить его зарегистрированному Bot.

1. В Cloud откройте раздел **Computers** вашего Bot и выберите **Add computer**, затем **Set up a computer**.
2. Выберите **Your own computer** и следуйте инструкциям. Cloud предоставляет команду установки и регистрации. Считайте код регистрации секретом: не отправляйте его в чат и не добавляйте в репозиторий.
3. Выполните команду на компьютере, который хотите подключить. Регистрация запускает процесс machine; оставьте его работать.
4. Проверьте, что компьютер подключён и назначен Bot. Если он не назначен, добавьте его в разделе **Computers** Bot. Тот же компьютер можно отдельно назначить другим Bots.

Процесс устанавливает исходящее соединение с Cloud. Когда он останавливается, компьютер отображается как offline. Регистрация не устанавливает фоновую службу: закрытие терминала или перезагрузка компьютера останавливает процесс. После регистрации запустите `klex-machine` от имени того же пользователя операционной системы, чтобы возобновить работу с сохранённой идентичностью. Защитите каталог идентичности, по умолчанию `~/.klex-machine`.

На вашем компьютере также может быть доступен совместимый рабочий стол. В macOS нужны активный сеанс и разрешения на запись экрана и универсальный доступ. В Windows нужен интерактивный сеанс входа. В Linux поддержка зависит от работающего дисплея и необходимых инструментов рабочего стола. Компьютер без рабочего стола всё равно может предоставлять инструменты для файлов и shell.

<a id="keep-a-linux-computer-connected"></a>

### Как оставить компьютер Linux подключённым

Администратор Linux может настроить службу systemd для запуска `klex-machine` при загрузке и перезапуска при сбое. Служба должна работать от имени нужного пользователя без привилегий и использовать его существующую идентичность machine. Сама по себе фоновая служба не предоставляет сеанс рабочего стола.

Проверьте службу перед включением. Защитите каталог идентичности и не запускайте службу от root без конкретной причины.

<a id="connect-locally-without-cloud"></a>

## Локальное подключение без Cloud

Для отдельного Bot на том же компьютере запустите сервер в локальном режиме:

```sh
# Установите один раз через npm или pnpm. Требуется Node.js 24 или новее.
npm install -g @klex/machine
klex-machine serve --mode local --cwd /path/to/workspace --port 3123
```

В настройках MCP-серверов Bot добавьте URL локального сервера `http://127.0.0.1:3123/mcp`. Оставляйте процесс работающим, пока Bot им пользуется.

Локальный режим не имеет аутентификации и по умолчанию использует интерфейс loopback. Не открывайте его для сети: любой, кто может подключиться к нему, может использовать сервер с правами пользователя операционной системы. Параметр `--cwd` меняет начальный каталог, а не границу доступа.

<a id="disconnect-a-computer"></a>

## Отключение компьютера

В Cloud выберите **Disconnect** на подключении компьютера Bot, чтобы отменить назначение этого Bot. Компьютер остаётся в организации, а другие назначенные Bots сохраняют доступ. Чтобы прекратить доступ через процесс machine на своём компьютере, остановите `klex-machine`; также проверьте назначения в Cloud и локальные учётные данные.
