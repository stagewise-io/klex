В большинстве подключённых приложений бот действует через собственную учётную запись. Настройте её разрешения в приложении. Предоставляйте боту только доступ, необходимый для назначенной работы, и пересматривайте его при изменении работы.

<a id="before-connecting-an-app"></a>

## Перед подключением приложения

1. Определите ресурсы и действия, необходимые боту. Начните с доступа только для чтения, если этого достаточно.
2. Предоставьте учётной записи бота доступ к нужным проектам, папкам или разговорам, а не ко всей организации, если приложение поддерживает такое ограничение.
3. Проверьте, может ли запись делиться данными, изменять настройки, удалять ресурсы или выполнять другие чувствительные действия. Удалите ненужные разрешения.
4. Протестируйте нужный процесс с неконфиденциальными данными и проверьте результаты.

Повторяйте эту проверку для каждого подключения, включая компьютеры. Подключение MCP предоставляет боту возможности; подключённые учётная запись и среда определяют их доступ. См. [Подключения](/ru/bot/concepts/brain-and-computers).

<a id="review-and-remove-access"></a>

## Проверяйте и удаляйте доступ

Проверяйте разрешения периодически и при изменении роли бота. Если доступ больше не нужен, отзовите его в подключённом приложении и при необходимости отключите соответствующий MCP-сервер. Отключение сервера само по себе не отзывает разрешения учётной записи в приложении. При подозрении на инцидент следуйте процессу организации и рассмотрите остановку бота на время проверки доступа.

Сейчас Klex не поддерживает одобрение или ограничения отдельных действий. Не полагайтесь только на промпт для обеспечения границ разрешений; используйте средства контроля доступа подключённого приложения. См. [Управление ботом Klex](/ru/bot/guides/control-and-limits).
