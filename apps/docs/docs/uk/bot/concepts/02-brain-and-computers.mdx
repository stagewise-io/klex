Klex Bot працює в зовнішніх середовищах, підключених через MCP (Model Context Protocol). Сервер MCP може надавати доступ до цілого комп’ютера або застосунку, наприклад GitHub чи Google Workspace. Комп’ютери також підключаються через MCP.

Власне середовище Bot підтримує його роботу та керує його пам’яттю. Роботу він виконує в підключених комп’ютерах і застосунках.

<a id="choose-what-to-connect"></a>

## Що підключити

- **Комп’ютери** надають підключене середовище, у якому Bot може працювати.
- **Застосунки** надають доступ до свого середовища через сервер MCP.

Klex пропонує низку вбудованих серверів MCP. Ви також можете підключати інші сервери MCP. Вибір середовищ залежить від роботи, яку має виконувати Bot.

<a id="manage-a-bots-access"></a>

## Керування доступом Bot

Підключіть застосунки та комп’ютери, потрібні Bot для роботи. Для більшості MCP він діє через власний обліковий запис або ідентичність із дозволами, налаштованими для цього Bot.

<Tabs syncKey="hosting" hash={false}>
<Tab title="У хмарі">

Відкрийте свій Bot у Klex Cloud. Керуйте підключеннями застосунків у розділі **Connectors**, а підключеними комп’ютерами в розділі **Computers**. Ви також можете переглянути його активність у розділі **Activity**.

</Tab>
<Tab title="На власному хостингу">

У застосунку Klex керуйте з’єднаннями серверів у розділі **Settings → MCP Servers**. Інструкції див. у розділі [MCP і Klex Bots](/bot/concepts/mcp#add-a-remote-server-in-the-self-hosted-app). Локальну діагностику можна переглянути в розділі **Settings → Logs**.

</Tab>
</Tabs>

Налаштуйте дозволи облікових записів Bot і підключених застосунків безпосередньо в цих облікових записах і застосунках. Підключення сервера та надання доступу обліковому запису — окремі рішення. Перевіряйте обидва, визначаючи, до чого Bot може отримати доступ і що може робити.

Загальний огляд див. у розділі [Як працюють Klex Bots](/bot/concepts/how-bots-work). Про те, де зберігаються чати та пам’ять, див. у розділі [директорія даних](/bot/concepts/data-directory).
