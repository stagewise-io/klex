Кожен бот Klex зберігає розмови та пам’ять у своєму каталозі даних. У бота, розміщеного в Cloud, каталог міститься в хмарному середовищі. У самостійно розміщеного бота він міститься в локальній папці, що використовується для його даних.

Адміністратори можуть отримувати доступ до розмов і пам’яті через Admin API бота. Панель Klex Cloud слугує зворотним проксі та інтерфейсом для Admin API кожного бота.

## Пошук самостійно розміщеного бота

У самостійно розміщеному застосунку Klex 0.30.1 інтерактивний запуск за замовчуванням шукає ботів у `~/.klex/agents`. Якщо задано `KLEX_HOME`, використовується папка `agents` за цим шляхом. За допомогою `--data-dir` можна обрати каталог напряму; цей параметр має пріоритет над `KLEX_DATA_DIR`.

Наприклад, щоб відкрити бота, каталог даних якого вам уже відомий:

```sh
klex --data-dir /path/to/bot
```

Замініть приклад шляху фактичним каталогом бота. Щоб створити й налаштувати бота без інтерфейсу термінала, див. [швидкий старт](/bot/quickstart).

## Захист даних

Каталог може містити конфіденційну інформацію, зокрема конфігурацію та облікові дані. Обмежте доступ за допомогою дозволів операційної системи та захистіть створені копії. У системах із файловими режимами Unix Klex 0.30.1 запитує права лише для власника під час створення каталогу; права наявних каталогів він не змінює. Windows використовує списки керування доступом.

Перш ніж видаляти або переміщувати дані, перевірте свої процедури резервного копіювання та відновлення. Ця сторінка не описує підтримувану процедуру міграції чи відновлення, правила зберігання або обробку даних третіми сторонами.
