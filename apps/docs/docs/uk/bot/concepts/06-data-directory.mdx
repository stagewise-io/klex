Кожен бот Klex зберігає розмови та пам’ять у своєму каталозі даних. У бота, розміщеного в Cloud, каталог міститься в хмарному середовищі. У самостійно розміщеного бота він міститься в локальній папці, що використовується для його даних.

Адміністратори можуть переглядати розмови та навички через Admin API бота. Панель Klex Cloud слугує зворотним проксі та інтерфейсом для Admin API кожного бота.

## Як знайти й захистити дані бота

<Tabs syncKey="hosting" hash={false}>
<Tab title="Розміщений у Cloud">

Відкрийте бота в Klex Cloud, щоб переглянути його активність. Каталог даних міститься в хмарному середовищі. Про захист даних ботів у Cloud див. розділ [Конфіденційність даних](/cloud/data-privacy).

</Tab>
<Tab title="Самостійно розміщений">

<a id="find-a-self-hosted-bot"></a>
<a id="пошук-самостійно-розміщеного-бота"></a>

У самостійно розміщеному застосунку Klex інтерактивний запуск за замовчуванням шукає ботів у `~/.klex/agents`. Якщо задано `KLEX_HOME`, використовується папка `agents` за цим шляхом. За допомогою `--data-dir` можна обрати каталог напряму; цей параметр має пріоритет над `KLEX_DATA_DIR`.

Наприклад, щоб відкрити бота, каталог даних якого вам уже відомий:

```sh
klex --data-dir /path/to/bot
```

Замініть приклад шляху фактичним каталогом бота. Щоб створити бота без Cloud або запустити його без інтерфейсу термінала, див. [посібник з автономного налаштування](/bot/guides/standalone-setup).

<a id="protect-the-data"></a>
<a id="захист-даних"></a>

### Захист локального каталогу

Каталог може містити конфіденційну інформацію, зокрема конфігурацію та облікові дані. Обмежте доступ за допомогою дозволів операційної системи та захистіть створені копії. У системах із файловими режимами Unix Klex запитує права лише для власника під час створення каталогу; права наявних каталогів він не змінює. Windows використовує списки керування доступом.

Перш ніж видаляти або переміщувати дані, перевірте свої процедури резервного копіювання та відновлення.
