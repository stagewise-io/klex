[Model Context Protocol (MCP)](https://modelcontextprotocol.io/) з’єднує Klex Bot із зовнішніми середовищами. Сервер MCP може надавати доступ до комп’ютера або застосунку; Bot використовує можливості сервера для роботи з ними.

Klex пропонує вбудовані сервери MCP та підтримує інші сервери MCP. Доступні можливості залежать від сервера:

- **Інструменти** дають Bot змогу запитувати в сервера дії або інформацію.
- **Ресурси** надають вміст, який Bot може знаходити й відкривати.
- **Push-сповіщення** можуть доставляти повідомлення та інші події, якщо сервер підтримує [розширення Klex MCP Push Notifications](https://github.com/stagewise-io/klex/tree/main/packages/mcp-extension-push-notifications).
- **MCP Events & Triggers**, чернетка розширення MCP, дає Bot змогу знаходити та відстежувати підтримувані події сервера. Відстеження зберігається між чатами й перезапусками, але події під час простою можуть бути втрачені. Створення відстеження не налаштовує зовнішній сервіс.

Ці можливості MCP можуть спонукати Bot до роботи, коли надходить повідомлення або щось змінюється в застосунку. Вони залежать від підтримки та налаштування підключеного сервера; окремий шлюз для Klex не потрібен.

<a id="adding-a-server"></a>

## Додавання сервера

Керувати MCP-з’єднаннями Bot можна на панелі Cloud. Bot також може сам додати новий віддалений сервер MCP через HTTP або HTTPS. Ця можливість не дає змоги змінювати чи видаляти наявні конфігурації серверів. Якщо новий сервер потребує OAuth, користувач може авторизувати його в інтерфейсі Cloud.

Підключайте лише довірені сервери. З’єднання надає Bot доступ до можливостей сервера; доступ усередині застосунку також залежить від налаштованого там облікового запису та його дозволів. Перевіряйте з’єднання Bot і надавайте його обліковим записам лише необхідний доступ. Докладніше про керування доступом див. у розділі [З’єднання з комп’ютерами та застосунками](/bot/concepts/brain-and-computers).

Bot з’єднується із застосунком через MCP. Його обліковий запис міститься всередині застосунку й існує окремо від з’єднання.

<a id="add-a-remote-server"></a>

### Додавання віддаленого сервера

<Tabs syncKey="hosting" hash={false}>
<Tab title="У хмарі">

1. У Klex Cloud відкрийте свій Bot і виберіть **Connectors**. Для керування конекторами потрібні права власника або адміністратора організації.
2. У каталозі конекторів виберіть **Connect an MCP**, введіть URL і назву сервера та додайте потрібні заголовки в **Advanced options**.
3. Виберіть **Connect** і завершіть авторизацію, якщо з’явиться запит. Перевірте стан з’єднання, перш ніж покладатися на сервер.

</Tab>
<Tab title="На власному хостингу">

<a id="add-a-remote-server-in-the-self-hosted-app"></a>

В інтерактивному застосунку Klex можна додати сервер streamable HTTP:

1. Відкрийте **Settings → MCP Servers** і натисніть `a`.
2. Введіть унікальну назву сервера та абсолютний URL HTTP або HTTPS. Для віддалених сервісів, які передають облікові дані, використовуйте HTTPS.
3. Якщо сервер потребує власних заголовків, натисніть `a`, щоб додати кожну назву та значення. Зберігайте значення облікових даних у таємниці.
4. Натисніть `s`, щоб додати сервер, і перевірте його стан у списку. Збережена конфігурація сама по собі не означає, що сервер підключений.

Щоб переглянути сервер, виберіть його й натисніть Enter. На екрані деталей показано його стан, транспорт, кількість інструментів і підтримку push-сповіщень. Там `e` змінює конфігурацію, а `d` видаляє сервер після підтвердження. Під час видалення Klex видаляє локальні облікові дані OAuth і намагається відкликати токен, якщо провайдер це підтримує. Відкликання може не вдатися, тому окремо перевірте дозволи облікового запису в підключеному застосунку.

</Tab>
</Tabs>

Для авторизації через OAuth в інтерфейсі Cloud Bot має бути зареєстрований у Cloud і мати підключений тунель Cloud. Окремий Bot без реєстрації в Cloud не може використовувати цей потік авторизації через Cloud.

<a id="if-a-connection-needs-attention"></a>

## Якщо з’єднання потребує уваги

Сервер може потребувати авторизації або не підключитися. Перевірте стан з’єднання та завершіть потрібну авторизацію. Якщо підключитися все ще не вдається, перевірте адресу сервера, облікові дані та доступність сервера. Bot може використовувати лише можливості, які надає підключений сервер.
