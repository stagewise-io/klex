Klex Bot може використовувати підключений комп’ютер для роботи з файлами, виконання команд і, коли доступний робочий стіл, роботи з графічними застосунками. Bot є мозком, а комп’ютер — інструментом, яким він користується. Bot може використовувати кілька комп’ютерів, а один комп’ютер можна призначити кільком Bots.

Оберіть керований комп’ютер у Klex Cloud або підключіть власний через MCP-сервер `@klex/machine`. Доступні Bot інструменти залежать від комп’ютера та його конфігурації.

<a id="before-you-connect"></a>

## Перед підключенням

Підключення комп’ютера надає Bot значний доступ. `@klex/machine` може читати й змінювати файли та виконувати команди shell з правами користувача операційної системи, який його запускає. Робочий каталог не є ізольованим середовищем: абсолютні шляхи залишаються доступними. Робочий стіл може відкрити доступ до всього, що цей користувач може бачити чи використовувати.

За можливості використовуйте окремий обліковий запис без привілеїв або ізольований комп’ютер. Видаліть непотрібні облікові дані й конфіденційну інформацію та надавайте доступ лише Bots і людям, яким довіряєте. Важливі дії перевіряйте незалежно. Див. [Контроль і обмеження](/uk/bot/guides/control-and-limits).

<a id="use-a-managed-computer"></a>

## Використання керованого комп’ютера

У розділі **Computers** вашого Bot виберіть **Add computer**, а потім **Set up a computer**. Виберіть **Cloud computer**, розмір і налаштування доступу до інтернету, перевірте ціну та натисніть **Create computer**. Перевірте стан і можливі помилки підключення в Cloud: призначення саме по собі не гарантує, що комп’ютер підключено.

Керовані комп’ютери можуть надавати робочий стіл для графічної роботи, а також інструменти для файлів і shell. Коли екран доступний, його можна переглядати в Cloud. Адміністратор може взяти керування, а потім повернути його Bot. Поки керує людина, введення Bot на робочому столі заблоковане. Доступність екрана й інструментів залежить від доступності комп’ютера та активної підтримки робочого столу.

<a id="connect-your-own-computer-to-cloud"></a>

## Підключення власного комп’ютера до Cloud

На комп’ютері потрібен Node.js 24 або новіший. Адміністратор організації може налаштувати комп’ютер у Cloud і призначити його зареєстрованому Bot.

1. У Cloud відкрийте розділ **Computers** вашого Bot, виберіть **Add computer**, а потім **Set up a computer**.
2. Виберіть **Your own computer** і дотримуйтеся інструкцій. Cloud надає команду встановлення та реєстрації. Ставтеся до коду реєстрації як до секрету: не надсилайте його в чат і не додавайте до репозиторію.
3. Виконайте команду на комп’ютері, який потрібно підключити. Реєстрація запускає процес machine; залиште його працювати.
4. Перевірте, чи комп’ютер підключено та призначено Bot. Якщо його не призначено, додайте його в розділі **Computers** Bot. Той самий комп’ютер можна окремо призначити іншим Bots.

Процес встановлює вихідне з’єднання з Cloud. Коли процес зупиняється, комп’ютер відображається як offline. Реєстрація не встановлює фонову службу: закриття термінала або перезавантаження комп’ютера зупиняє процес. Після реєстрації запустіть `klex-machine` від імені того самого користувача операційної системи, щоб відновити роботу зі збереженою ідентичністю. Захищайте каталог ідентичності, за замовчуванням `~/.klex-machine`.

На власному комп’ютері також може бути доступний сумісний робочий стіл. У macOS потрібні активний сеанс входу та дозволи на запис екрана й доступність. У Windows потрібен інтерактивний сеанс входу. У Linux підтримка залежить від працюючого дисплея та необхідних інструментів робочого столу. Комп’ютер без робочого столу все одно може надавати інструменти для файлів і shell.

<a id="keep-a-linux-computer-connected"></a>

### Як залишити комп’ютер Linux підключеним

Адміністратор Linux може налаштувати службу systemd для запуску `klex-machine` під час завантаження та перезапуску в разі збою. Служба має працювати від імені потрібного користувача без привілеїв і використовувати його наявну ідентичність machine. Сама по собі фонова служба не забезпечує сеанс робочого столу.

Перевірте службу перед увімкненням. Захистіть каталог ідентичності та не запускайте службу від root без конкретної причини.

<a id="connect-locally-without-cloud"></a>

## Локальне підключення без Cloud

Для окремого Bot на тому самому комп’ютері запустіть сервер у локальному режимі:

```sh
# Установіть один раз через npm або pnpm. Потрібен Node.js 24 або новіший.
npm install -g @klex/machine
klex-machine serve --mode local --cwd /path/to/workspace --port 3123
```

У налаштуваннях MCP-серверів Bot додайте URL локального сервера `http://127.0.0.1:3123/mcp`. Залишайте процес працювати, поки Bot ним користується.

Локальний режим не має автентифікації та за замовчуванням використовує інтерфейс loopback. Не відкривайте його мережі: будь-хто, хто може до нього підключитися, може використовувати сервер з правами користувача операційної системи. Параметр `--cwd` змінює початковий каталог, а не межу доступу.

<a id="disconnect-a-computer"></a>

## Відключення комп’ютера

У Cloud виберіть **Disconnect** на підключенні комп’ютера Bot, щоб скасувати призначення цього Bot. Комп’ютер залишається в організації, а інші призначені Bots зберігають доступ. Щоб припинити доступ через процес machine на власному комп’ютері, зупиніть `klex-machine`; також перевірте призначення в Cloud і локальні облікові дані.
