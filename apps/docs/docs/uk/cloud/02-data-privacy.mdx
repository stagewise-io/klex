Чати й пам’ять бота зберігаються в його [каталозі даних](/uk/bot/concepts/data-directory). Для бота в Cloud цей каталог розташований у хмарному середовищі. Для самостійно розміщеного бота він розташований у середовищі, де ви його запускаєте. Адміністратори можуть переглядати чати й навички через Admin API бота.

Усі дані ботів у Cloud, включно з пам’яттю, шифруються під час передавання та зберігання. Це твердження не описує шифрування самостійно розміщених ботів; належним чином захищайте власне середовище та сховище.

<a id="access-and-connected-services"></a>

## Доступ і підключені служби

Бот може працювати з підключеними застосунками через дозволи своїх облікових записів. Перш ніж використовувати конфіденційну інформацію, перевірте дані й дії, доступні кожному запису, а також політики підключених служб і постачальників моделей. Див. [Безпечне використання ботів Klex](/uk/guides/secure-bot-usage).

Для налагодження бота в Cloud обмежене коло працівників Klex може отримати доступ до його чатів або пам’яті в режимі налагодження після обговорення з вами розслідування та отримання вашого підтвердження. Цей доступ постійно реєструється, видимий вам і зазвичай обмежений у часі. Він не призначений для загального навчання моделей.

[Політика конфіденційності](https://klex.bot/legal/privacy) та [Угода про обробку даних](https://klex.bot/legal/data-processing-agreement) описують налагодження підтримкою, іншу обробку, постачальників послуг і зберігання. Вони також окремо розглядають законну обробку з міркувань безпеки чи правових підстав. Перевірте застосовні умови й політики підключених постачальників для вашого випадку.

<a id="analytics-and-telemetry-for-a-self-hosted-bot"></a>

Klex має дві окремі системи звітності. Наведені нижче засоби застосовуються до самостійно розміщеного процесу Klex; вони не описують звітність на стороні Cloud або підключені служби.

**Аналітика продукту** ввімкнена за замовчуванням у випусках, що містять ключ аналітики. Події можуть включати результати запуску й підключення, агреговані показники використання, інформацію про виконання та використання ресурсів процесу. Схеми подій не містять вмісту чатів або токенів підключення. Кожен процес використовує тимчасовий випадковий ідентифікатор, а мережевий запит розкриває IP-адресу відправника одержувачу. Див. [подробиці реалізації аналітики продукту](https://github.com/stagewise-io/klex/blob/baff8a40ce9b896fdd17146dfe9906cefe7c2697/apps/klex/product-analytics.md).

Щоб вимкнути аналітику продукту, запустіть Klex із `--no-analytics` або встановіть `KLEX_NO_ANALYTICS=1` чи `DO_NOT_TRACK=1` у його середовищі. Явний прапорець `--analytics` має пріоритет над вимкненням через змінні середовища.

**Операційна телеметрія** працює окремо. Вона вимкнена, якщо кінцеву точку телеметрії не налаштовано. Якщо телеметрію явно не вимкнено, налаштування кінцевої точки вмикає її. Увімкнений за замовчуванням рівень містить конфіденційні операційні метадані. Рівень налагодження також може експортувати вміст чатів, промпти та дані інструментів. Використовуйте лише довірений колектор і обмежуйте доступ до його даних. Щоб примусово вимкнути телеметрію, використовуйте `--disable-telemetry` або `KLEX_DISABLE_TELEMETRY=1`. Див. [подробиці реалізації телеметрії](https://github.com/stagewise-io/klex/blob/baff8a40ce9b896fdd17146dfe9906cefe7c2697/apps/klex/telemetry.md).

Вимкнення однієї системи не вимикає іншу. Жоден із цих засобів не вимикає зв’язок із налаштованими постачальниками моделей, MCP-серверами чи підключенням до Cloud.
