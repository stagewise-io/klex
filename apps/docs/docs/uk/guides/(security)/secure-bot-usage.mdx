У більшості підключених застосунків бот діє через власний обліковий запис. Налаштуйте дозволи цього запису в застосунку. Надавайте боту лише доступ, потрібний для призначеної роботи, і переглядайте його, коли робота змінюється.

<a id="before-connecting-an-app"></a>

## Перед підключенням застосунку

1. Визначте ресурси та дії, потрібні боту. Почніть із доступу лише для читання, якщо цього достатньо.
2. Надайте обліковому запису бота доступ до відповідних проєктів, папок або розмов, а не всієї організації, якщо застосунок підтримує таке обмеження.
3. Перевірте, чи може запис поширювати дані, змінювати налаштування, видаляти ресурси або виконувати інші чутливі дії. Видаліть непотрібні дозволи.
4. Протестуйте потрібний процес із неконфіденційними даними та перевірте результати.

Повторюйте цю перевірку для кожного підключення, зокрема комп’ютерів. Підключення MCP надає боту можливості; підключений обліковий запис і середовище визначають їхній доступ. Див. [Підключення](/uk/bot/concepts/brain-and-computers).

<a id="review-and-remove-access"></a>

## Переглядайте та видаляйте доступ

Перевіряйте дозволи періодично та зі зміною ролі бота. Якщо доступ більше не потрібен, відкличте його в підключеному застосунку та за потреби відключіть відповідний MCP-сервер. Відключення сервера саме по собі не відкликає дозволи облікового запису в застосунку. Якщо підозрюєте інцидент, дотримуйтеся процесу організації та розгляньте зупинку бота на час перевірки доступу.

Наразі Klex не підтримує схвалення чи обмеження окремих дій. Не покладайтеся лише на промпт для забезпечення меж дозволів; використовуйте контроль доступу підключеного застосунку. Див. [Керування ботом Klex](/uk/bot/guides/control-and-limits).
