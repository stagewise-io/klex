Бот для спілкування з клієнтами має отримувати доступ лише до інформації та дій, потрібних для відповіді на запити підтримки. Не припускайте, що прохання зберегти секрет достатньо для запобігання його розголошенню.

<a id="reduce-what-the-bot-can-access"></a>

## Обмежте доступ бота

- Не надавайте боту доступу до облікових даних продуктивного середовища, конфіденційних записів клієнтів або внутрішніх документів, які йому не потрібні.
- Використовуйте окремі облікові записи з обмеженими правами для підтримки, якщо підключена служба це дозволяє. Перевірте їхній доступ до читання, поширення та зміни даних.
- Не включайте облікові дані до розмов підтримки та прикладів. Для інтеграцій використовуйте затверджений у вашій організації процес керування обліковими даними.
- Перевірте, хто може звертатися до бота та бачити його відповіді в кожній підключеній службі.

<a id="review-the-workflow"></a>

## Перевірте робочий процес

Тестуйте з неконфіденційними даними, зокрема із запитами на отримання інформації поза передбаченою сферою. Перевірте результати й дозволи в підключених службах; не припускайте, що бот завжди відхилятиме зловмисні запити.

Якщо облікові дані або конфіденційну інформацію могли розкрити, дотримуйтеся процесу реагування на інциденти. Відкличте або замініть відповідні облікові дані та перевірте пов’язані доступи й активність. Див. [Запобігання крадіжці інформації](/uk/guides/prevent-information-theft) і [Обмеження наслідків](/uk/guides/limit-blast-radius).
