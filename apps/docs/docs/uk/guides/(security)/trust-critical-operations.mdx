Не припускайте, що бот завжди ухвалить правильне рішення або бездоганно виконає інструкції. Для конфіденційної або важливої роботи оцініть наслідки помилкової дії та запровадьте незалежні засоби захисту.

<a id="start-with-lower-risk-work"></a>

## Починайте з менш ризикованої роботи

- Дозвольте боту зібрати інформацію або підготувати пропозицію зміни, перш ніж надавати йому доступ для її застосування.
- Тестуйте на непродуктивних ресурсах і перевіряйте результати. Розширюйте доступ лише після розуміння робочого процесу та обробки збоїв.
- Обмежте дозволи облікового запису бота в кожному підключеному застосунку. Не надавайте руйнівних або конфіденційних дозволів, якщо вони не потрібні.

<a id="keep-an-independent-check"></a>

## Забезпечте незалежну перевірку

Для операцій, що потребують схвалення людини, організуйте таке схвалення поза ботом до застосування зміни. Наприклад, бот може підготувати зміну, яку людина перевірить і застосує через окремий обліковий запис. Зараз Klex не підтримує схвалення чи обмеження окремих дій; інструкція спочатку запитати не є примусовим контролем схвалення.

Використовуйте засоби підключеної служби та процеси організації для перевірки активності, виявлення проблем і виправлення помилок. Заздалегідь вирішіть, як за потреби зупинити бота та відкликати доступ. Див. [Керування ботом Klex](/uk/bot/guides/control-and-limits) і [Обмеження наслідків](/uk/guides/limit-blast-radius).
