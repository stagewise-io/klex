通过限制 Bot 账号和连接环境的访问权限，减少 Bot 遭入侵时可能造成的影响。合适的边界取决于所涉及的应用、计算机和数据；仅靠对 Bot 的指示并不能控制访问。

<a id="reduce-exposure"></a>

## 减少暴露

- 连接的应用支持时，为 Bot 使用独立账号。只授予其工作所需的资源和权限。
- 将敏感资源与一般工作分开。除非 Bot 需要，否则避免连接生产系统或敏感数据。
- 利用相关服务提供的访问控制，限制谁可以接触 Bot 以及它使用的对话或工具。
- 检查分享信息、更改设置和执行破坏性操作的权限。对影响重大的更改使用独立的审批流程。
- 定期检查访问权限，移除不再需要的连接和授权。

账号权限检查清单请参阅[安全使用 Klex Bot](/zh/guides/secure-bot-usage)。

<a id="prepare-to-respond"></a>

## 准备响应

在事件发生前了解 Bot 使用的账号、连接和环境。如果怀疑遭到入侵，请遵循事件响应流程：考虑停止 Bot、撤销连接服务中的访问权限、轮换受影响的凭据并检查相关活动。仅停止 Bot 不能替代撤销访问权限或调查已经执行的操作。
