Klex 是一个开源、可自托管的系统，用于创建和运行机器人（完全自主的代理），专为团队用 AI 驱动的数字同事来扩展其劳动力而构建。Klex 由 [stagewise](https://stagewise.io) 构建，采用 Apache-2.0 许可证。

<GithubInfo owner="stagewise-io" repo="klex" />

单个 Klex 机器人就像一个独立的身份。它有自己的个性、自己的记忆，并在你所有的工作平台中拥有自己的身份。

我们**不**喜欢将 Klex 机器人称为"助手"，因为虽然你*可以*创建一个以担任你的助手为工作的 Klex 机器人，
但 Klex 机器人比这强大得多，允许你创建一整队与同事协作的机器人团队，无论同事是人类还是机器人。

## 我们的核心原则

我们构建的一切都遵循六个原则：

- **开源且模型无关** — 无供应商锁定。随时更改模型，或在你自己的基础设施上运行机器人。
- **自有身份** — 机器人以自身身份行事，而非代表他人。每个集成都以此理念构建。
- **易用性** — AI 驱动的劳动力应该人人可用。我们推崇**易用性高于自定义**，保持设置和维护简单。
- **标准合规** — 所有外部通信都通过 [**MCP**](https://modelcontextprotocol.io/docs/2026-07-28/getting-started/intro) 进行 — 无自定义网关。通信平台通过 MCP 加上一个让应用程序主动触发机器人的小型扩展来连接。记忆系统也与 [**Agent Skills**](https://agentskills.io/home) 兼容，用于存储程序性记忆。
- **可内省性** — 机器人的记忆以纯 Markdown 格式存储。你可以随时阅读和检查机器人知道的一切。
- **适应性** — 机器人仅访问通过 MCP 显式连接的机器 — 从不访问它们运行所在的主机。它们无法内省自己的原始记忆、更改自己的性格或修改主机设置。这从设计上保证了操作安全。

## Klex 云端

我们的机器人伴随着名为 [**Klex 云端**](https://cloud.klex.bot) 的云服务，该服务为各种平台托管 Klex 兼容的 MCP 服务器。

我们的云端还帮助在这些平台中为你的机器人提供专属身份（通过账户、机器人实例或应用程序），让你轻松赋予机器人可以以其身份行事的独立身份。

<Panel title="须知">
云服务是**完全可选的**，如果你想确保没有任何通信数据通过第三方提供商传输，可以忽略它。
</Panel>

对于企业客户，我们提供云服务的本地可托管变体，确保满足有关数据韧性等方面的所有合规需求。
